# 趋势线与历史交易回放性能优化：实施与验证

2026-10-18 实施趋势线与历史回放绘图投影优化。本文件合并原诊断基线、验收意图和实施验证；下列性能与测试结果均为当时记录，未在本次文档整理中重跑。

## 已实现

1. **统一已加载时间轴。** `ReplayChart` 为完整已加载 `bars` 提取时间、桶结束时间和源序号范围，供两个绘图 primitive 共享。隐藏只改变蜡烛、成交量、指标和选根可见性，绘图仍使用保留 whitespace 的同一时间轴。隐藏区新画的端点保留合法的 `sourceSequence=null`，使用已加载时间槽定位，不读取隐藏 OHLC，也不生成虚假源序号。
2. **共享二分索引与交易日日历。** 新增 `drawing-timeline.ts`，对时间和源序号二分定位。窗口内保留源序号包含关系和缺失行情的插值规则；窗口外源序号端点改用其真实时间沿交易日历外推，避免用跨休市的源序号差假定显示桶连续。`aggregation.ts` 将时段边界提取为共用实现，日历按交易日累计桶数，首尾桶按各日实际边界计算，保留 RTH、ETH、周末、DST 和尾部短桶。
3. **定位缓存与重绘合并。** 同一图表的趋势线、斐波那契、草稿和拖动预览共享定位器。位置缓存不包含价格和样式；平移、缩放、价格轴和样式变化只需刷新屏幕坐标。每个端点/日历位置/反向槽位缓存最多 4,096 项，日历最多 36,600 个自然日。超限返回无法投影，交互层拒绝该端点；不会返回截断位置或按墙钟时间伪造位置。完整窗口追加、补页、裁剪、同长度替换和修订按真实不可变数组更新索引；未改动的 K 线通过 WeakMap 复用元数据和数值索引。周期、时段和会话作用域变化会清理对应缓存。多处 effect 和指针事件在同帧合并为一次绘图同步，卸载取消待处理帧。
4. **有限线段裁剪。** 确认与视口不相交后跳过线段绘制和线体命中；两端都在屏幕外但穿过视口的线段仍保留。选中端点、草稿、价格标签、Fib 标签及对象坐标仍按原有规则处理，不删除对象或改写保存数据。

## 原诊断基线与验收意图

原问题出现在隐藏未来行情时：K 线时间轴保留已加载时间槽，绘图投影却只收到可见前缀；纯时间端点因而被当成窗口外端点，重绘时反复逐桶计算交易时段和时区。窗口内部分查询也使用线性扫描。合法的 `sourceSequence=null` 表示端点只有时间锚点，不能据此删除绘图或补造源序号。

2026-10-18 的本机只读基线使用 19 条趋势线、38 个端点（其中 3 个只有时间锚点），源周期 1 分钟、显示周期 5 分钟、RTH；最多读取 24,000 根源行情，生成 1,200 根历史窗口。计时调用真实 `TrendLinePrimitive.updateAllViews`，图表坐标使用轻量替身；每个场景预热 1 次、采样 3 次，不含数据库读取、聚合、HTTP 或 Canvas 绘制：

| 场景 | 绘图数 | 投影中位耗时 | 每次时区换算数 |
| --- | ---: | ---: | ---: |
| 最近 300 根窗口 | 19 | 0.5 ms | 0 |
| 完整 1,200 根窗口 | 19 | 1.8 ms | 0 |
| 隐藏后半段，仅传 780 根前缀 | 19 | 41.3 ms | 1,674 |
| 同一隐藏前缀，内存夹具排除含纯时间端点的线 | 16 | 0.2 ms | 0 |
| 同一隐藏前缀，无绘图 | 0 | <0.1 ms | 0 |

排除线条只是内存对照，没有改写业务绘图。该基线说明慢路径与远距离纯时间端点有关，不代表完整页面性能。原验收意图包括：统一绘图使用的已加载时间轴；共享按时间/源序号定位和有界缓存；覆盖窗口增量、补页、裁剪、替换、周期、时段、会话及数据版本变化；避免每次平移、缩放或样式变化重算交易日距离；保留 RTH/ETH、周末、DST、缺失行情、尾部短桶和跨休市锚点语义；有限裁剪只跳过确认不穿越视口的线段；用浏览器交互检查补足 primitive 微基准。以下实施与验证按这些目标记录。

## 本机投影测量

复用本机 ES「模拟训练」的 19 条趋势线、38 个端点，其中 3 个仅有时间。源周期 1 分钟，显示周期 5 分钟，RTH；最多读取 24,000 根源行情。数据库以只读方式打开，读取后关闭，再计时。推进测量使用最后一根已揭示源行情的真实修订或已揭示显示桶的追加，不读取未来行情。

单位 ms。首次包含索引建立和一次投影；重复列为 30 次更新的中位数；窗口更换为左侧裁剪一次后的索引和投影更新。计时不含数据库、HTTP 和 Canvas 绘制。

| 场景 | 首次 | 重复 | 推进 / 追加 | 窗口更换 |
| --- | ---: | ---: | ---: | ---: |
| 实际 19 条，300 根窗口 | 2.84 | 0.11 | 0.31 | 0.23 |
| 实际 19 条，1,200 根历史窗口 | 1.18 | 0.08 | 0.24 | 0.20 |
| 隐藏价格，保留完整 1,200 根时间轴 | 0.86 | 0.08 | 0.22 | 0.22 |
| 仍仅传 780 根前缀，隔离检验新定位器 | 0.86 | 0.07 | 0.22 | 0.21 |
| 16 条远距离纯时间线，1,200 根窗口 | 1.29 | 0.07 | 0.32 | 0.26 |
| 50 条远距离纯时间线，1,200 根窗口 | 2.18 | 0.18 | 0.46 | 0.43 |
| 200 条远距离纯时间线，300 根窗口 | 15.89 | 0.67 | 2.03 | 1.43 |
| 200 条远距离纯时间线，1,200 根窗口 | 5.85 | 0.57 | 1.30 | 1.36 |

所有场景的重复投影时区换算均为 **0**。原计划的隐藏前缀基线为每次约 **41.3 ms / 1,674 次换算**；新定位器在保留同类前缀输入时首次约 0.86 ms、重复约 0.07 ms。实际隐藏路径现在还保留完整时间轴。初次计算仍取决于日期跨度和新端点数量，不承诺所有冷启动均低于一帧。

```powershell
corepack pnpm run benchmark:drawing-projection
# 可选：显式传入已有数据库的绝对路径，仍以只读方式打开
corepack pnpm run benchmark:drawing-projection D:/path/to/existing.db
```

[测量脚本](../scripts/benchmark-drawing-projection.ts)。原始结果保存在被 Git 忽略的 `tmp/trend-line-diagnosis/projection-after.json`；诊断基线为同目录 `projection-baseline.json`。合成场景使用 16 / 50 / 200 条绘图和 300 / 1,200 根窗口，端点向两侧最多延伸 200 天。

## 浏览器与交互

使用数据库副本和独立生产构建，在 Edge 中验证实际普通回放页和历史只读页。访问 `http://replay-test.local:3107`，域名仅在测试浏览器内映射到本机；确认 `isSecureContext=false`，并主动禁用 `crypto.randomUUID`。验证服务的资源哈希已与新构建核对；误加载旧构建的早期排查结果未计入下列统计。

- 普通回放连续推进 5 根显示 K 线，已揭示源数从 32,869 到 32,894；绘图创建、对象窗口、端点拖动、隐藏/恢复、平移/缩放、1m / 2h / 5m、ETH / RTH 切换均通过。
- 历史页本次实际窗口包含 486 根聚合 K 线；隐藏后保留时间轴，恢复后可见数回到完整窗口数。历史本地绘图刷新后语义内容一致，历史验证未发出业务写入请求。
- 普通页与历史页均检查 375 / 1280 / 1440 / 1920px 截图。布局、图表尺寸、工具栏滚动和隐藏提示未发现本次改动引入的异常；无新增控件、文案、颜色或 UI 规范例外。
- 页面运行错误为 0。普通连续推进和绘图创建阶段未记录到超过 50 ms 的长任务；普通隐藏/平移/缩放阶段有一次 59 ms 任务。历史隐藏/平移/缩放阶段未记录到长任务，其帧间隔 P95 约 6 ms（本机显示刷新环境）。
- 页面加载仍有 51–113 ms 的一次性任务；历史页调整到 1920px 时记录到一次 123 ms 任务。因此本次结果证明端点投影慢路径已消除及持续交互改善，不能解释为整页所有任务均已低于单帧预算，也不将本机帧间隔视为其他设备的保证。
