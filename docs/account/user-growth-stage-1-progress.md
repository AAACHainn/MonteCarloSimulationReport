## 实现与数据边界

- 独立入口 `/preview/user-growth`，保留原工作台导航与标准页面宽度；没有将演示选择器接入正式 Header 或回放业务。
- `components/user-growth/` 提供可复用的身份区、境界轨迹、条件账页、成长记录、会话列表、选择器、资料表单和历史归属弹窗。视图通过 `lib/user-growth/types.ts` 接收展示数据及操作回调。
- 演示输入集中在 `lib/user-growth/preview-data.ts`，控制与内存状态位于 `components/user-growth/preview.tsx`。没有实现成长结算服务、API、用户持久化、浏览器选择记忆或数据库模型。演示控件不会成为正式调经验入口。
- 固定状态包含凡人 0 / 95 经验、炼气六层、十二层准备、经验足够但成果不足、可突破、筑基一层、长昵称与大金额；额外提供加载、查询失败、空用户、空历史、保存失败、头像损坏和归属冲突。
- 创建与编辑共用表单，展示四个可替换的中性头像占位；支持本地 PNG / JPEG / WebP 选择、格式与 5 MiB 限制、圆形裁切预览、键盘缩放和位置调整。这里只保存本页内存中的展示参数，不上传、编码或落盘用户图片。正式人物素材及服务端上传留给第五阶段。
- 历史归属只在具体档案会话区出现；演示搜索、模式筛选、分页、跨页选择、普通确认、整批冲突与有效选择保留。成功仅修改内存会话行，不改变经验及条件。
- 可分别改变当前选择、档案查看对象，并打开固定会话归属的上下文窗口；没有改变真实账户、回放位置或在途业务操作。
- 突破只是界面模拟：失败保留进度；成功替换境界文字、收起原条件、保留累计值、插入演示达成记录，焦点落在新境界标题。无二次确认、成功概率或时间门槛。

V1 建议数值只作为固定演示输入沿用原文档；没有修改奖励与突破规则，也没有增加登录、权限、会话复盘奖励或未开放境界的规则。

## 第一轮体验反馈处理（2026-10-25）

开始本轮时工作区保留第一阶段全部未提交文件，已重新核对 Git 状态与当前代码；未回退、覆盖或提交既有工作区改动。

### 反馈与实际调整

1. **成长记录积累几千条如何处理：** 成长事实完整保留，不因条数增长而删除旧历史。档案仅接收最近 5 条及总数，“查看全部记录”改为分页窗口，每页 20 条，包含首页、上一页、下一页、末页。新增“5,000 条历史 · 分页”场景；模拟数据源只按当前页生成最多 20 条，不构造 5,000 条数组。正式接入的服务端分页已写入设计，本轮未实现数据库查询或声称已存储真实历史。
2. **只记录 USDT：** 移除“分币种实得”及其他币种演示数据，成长展示模型也不再含分币种累计字段；保留六项条件中的 USDT 实得。同步更新设计与后续计划中的金额口径。现有交易账户的币种设置尚未改动，取消全局币种设置另行实施。
3. **两个区域高度不一致：** 筑基条件、最近成长记录改为上下排列，相同宽度、间距 24px；成长行采用左侧事件和来源、右侧时间与操作的布局。展开或收起条件均不再留下并列空白，不强行拉高空容器。
4. **切换用户后资料未切换：** 经代码核对，这不是等待后台接入才能工作的限制。按原设计，“当前选择”和“查看对象”独立；右上角选择用户不自动跳离正在看的档案。选择后打开菜单中的“用户档案”可查看所选用户，也可从全局档案列表查看其他人。本轮按用户要求保留此行为，不另行改变选择与归属规则。
5. **尚未创建用户的回放提示：** 确认空用户场景时，上下文示例、打开的回放窗口和普通新建归属展示“未创建用户”。存在用户但会话没有归属时仍显示“未归属”；列表查询失败不作为尚未创建用户。实际回放工具栏的接入仍属于第二阶段，本轮使用共享 `SessionOwnership` 组件完成预览。

主要文件：`growth-record-list.tsx`、`growth-records-dialog.tsx`、`session-ownership.tsx`、`profile-view.tsx`、`preview.tsx`、`lib/user-growth/types.ts`、`lib/user-growth/preview-data.ts`、集中中文文案及本目录设计/计划。新增组件按展示输入和回调复用，没有增加真实用户、归属或成长 API。
