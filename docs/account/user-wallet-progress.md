## 确认的范围

- 名称为“自有资金账户”“自营公司账户”。每个实际用户一次性获得 10,000 USDT，新旧用户相同；不追算历史盈利或出金，余额为 0 不补发。本版没有任务、充值或资金救济。
- 只有归属用户的模拟训练参与余额。全部用户仅为查看范围，未归属会话和实盘重演完全排除；财务归属以会话所属用户为准。
- USDT 在账户创建前端固定，模板摘要默认显示 USDT；原数据库币种字段、后端币种兼容能力保持。
- 自有资金先扣可用余额并记录分配；初始本金不能超过可用余额。用户档案区分可用余额和账户内资金，后者为本金加已实现盈亏减手续费，不含浮动盈亏。资金必须提取后才能再次使用。
- 自营购买和每轮重考检查购买费与激活费合计是否足够，只扣购买费；通过考核并确认转为出金账户时再检查、扣激活费。成功出金只增加交易者实际收到的金额，遵守既有提款门槛、比例和上限。
- 删除自有账户明确“提取资金并删除会话”；自营账户在可出金时明确“出金并删除会话”，提示分成后实得及剩余放弃利润。不满足提款规则时仅允许明确放弃删除，购买费和激活费始终不退。行情删除不能绕过未结清账户。
- 用户账本不随会话级联删除，记录初始发放、存入、提取、购买、激活与出金，保留来源名称和轮次；账本与账户列表每页 20 条，不裁剪历史。

## 实现与保护

新增 `UserWallet`、`UserWalletEntry`、`UserWalletAllocation`，以整数分保存金额。交易账户原有浮点计算保持，结算边界统一四舍五入到分。新增迁移 `20261026140000_user_wallet` 与初始化脚本复用相同 SQL，初始发放幂等。

已有用户的期初钱包与初始流水时间取原用户创建时间，作为一次性期初记录，不代表恢复了历史发放。这样副本演练与实际升级得到相同数据，避免使用各自执行时间导致完整指纹不同。新建用户仍以实际创建时间记账。

资金、账户、轮次、出金、成长及删除在同一 SQLite 写事务完成。来源唯一键防重复记账，余额版本校验防冲突；失败保留原会话和原余额。删除前读取金额预览，提交时重新校验版本、条件和金额。前端提示不足，服务端仍负责最终检查。
