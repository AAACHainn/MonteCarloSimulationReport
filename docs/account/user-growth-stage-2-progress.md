## 实际实现

- `/users`、`/users/[userId]` 接入数据库中的用户列表、创建、昵称修改与个人会话。复用第一阶段的身份区、境界轨迹、资料弹窗、历史归属列表和默认头像，正式页面不提供头像上传或成长修改入口。
- 全局 Header 与实际回放工具栏接入同一用户选择上下文。浏览器只保存选择 ID；默认全部用户，存储不可用时保留本次内存选择。网络失败保留已知选择；完整列表确认 ID 不存在才回到全局并提示。请求取消和版本检查阻止旧响应覆盖新选择，支持其他标签页的选择变化。
- 当前选择、正在查看的档案、正在打开的会话归属分别展示。直接链接仍可查看其他人的会话。切换不跳转、重建账户或改变当前回放进度。个人筛选作用于回放会话及其日志选择，不改变共享行情、模板、独立交易日志或蒙特卡洛数据。
- 普通新建在提交时固定 `userId`，服务器校验用户；无效用户报错，不静默变成未归属。重新开始继承来源的用户与资格；历史归属和未归属不会因重新开始变成成长会话。实盘重演派生保持无成长资格。同会话重新考核保留原归属与资格。原确认流程展示继承说明。
- 历史归属入口仅在个人档案。服务器按名称、模式和页码查询未归属会话，每页最多 20 条；勾选跨页保留，每批最多 200 个。整批事务重新核对资格，冲突或写入失败均不产生部分归属；响应返回冲突 ID，界面显示对象名称、移除失效选择并保留有效选择。分页和选择栏在短窗口内持续可见。
- 建立 `UserProfile`、`UserGrowth`、`UserGrowthFact`、`UserRealmRecord`，以及会话 `userId`、`ownershipSource`、`growthEligible`、`assignedAt`。独立事实保留来源唯一键、本轮首次出金唯一键、实际结算增量、规则版本与摘要；USDT 实得以整数最小单位保存。来源会话是普通标识，不建立会随来源删除的级联关系；累计投影和突破快照、幂等键为后续阶段预留。

成长结算、炼气升级、自营奖励、突破、正式头像均未接入。本阶段只保存初始零累计，不生成成长事实，不从旧会话补算。真实档案将成长区域明确标为尚未接入；第一阶段演示经验不会混入真实档案。第二阶段试验交易不承诺第三阶段自动回溯奖励。

## 用户手动验收

1. 打开档案列表，通过右上角圆形头像切换用户并刷新，预期选择记忆正确。直接打开某人档案仍只改变查看对象；在档案详情主动通过头像菜单选另一人，标题和会话同步切换，选全部用户返回列表。编辑昵称后列表、菜单及档案同步。验收甲现已由用户改名为“修改后的甲”，不还原该编辑。
2. 打开合成行情会话列表，依次选择甲、乙和全部用户。预期个人仅显示本人会话，全局显示全部；行情仍共享。普通新建表单显示当前归属，提交后不随之后的选择变化。
3. 从甲档案打开甲的普通训练，推进一根后切到乙。预期会话仍归甲，位置和账户不变；顶部明确当前选择与实际归属。已有其他用户会话链接仍可直接打开。
4. 在甲档案归属未归属练习，翻页、筛选再返回，确认选择数保留；提交后出现“历史归属 · 不参与成长”，初始经验不变化。可用两个页面重复竞争同一对象，预期后一批整批失败，失效项移出且其余勾选保留。
5. 在验收副本的成长资格、历史归属或未归属会话中使用原“重新开始”流程。预期确认说明和新会话继承原归属/资格；当前选择不同也不改变结果。三个“人工失败样例”可直接打开自营面板试用“重新考核”，预期只新增业务轮次，归属/资格保持原值。
6. 确认成长区域明确标为尚未接入，没有演示经验、奖励领取、突破或正式上传入口。本阶段交易只用于归属验收，不承诺后续补发。
