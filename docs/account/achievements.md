# 用户成就

> 文档状态：当前规范。适用范围：个人成就、展示徽章、后台增量、历史补算与维护入口。

成就仅奖励徽章。归属、资格及原业务计数单位沿用[用户档案与成长](user-growth-design.md#4-成长资格与计数单位)。已解锁阶段独立保存，归档或删除来源不会撤销徽章。经验、资金、撮合与账户规则继续由各自业务结算。

## 成就目录

| 系列 | 阶段 | 认定依据 |
| --- | --- | --- |
| 初试锋芒 | 1 | 首个完整持仓周期 |
| 百炼成钢 | 100 / 500 / 1000 | 累计完成的完整持仓周期 |
| 落笔为证 | 1 | 首次有效逐笔复盘 |
| 复盘成册 | 10 / 50 / 100 | 累计有效逐笔复盘，每笔只计首次 |
| 过关斩将 | 1 / 5 / 10 / 20 | 累计通过自营考核，每个会话的每轮只计一次 |
| 兑现时刻 | 1 / 5 / 10 / 20 | 成功出金流水，含同轮后续出金 |
| 长青账户 | 3 / 5 | 同一会话的同一轮次成功出金 |
| 破境之证 | 1 | 原成长系统的实际筑基突破 |
| 逆风而行 | 5 / 10 | 同一会话、同一轮次连续纯保护止损的完整周期 |
| 乘风而上 | 5 / 10 | 同一会话、同一轮次连续纯保护止盈的完整周期 |

部分减仓沿原完整周期保存实际退出原因。只有周期内每次减仓的退出原因都是同类保护单成交，才计为纯止损或纯止盈。手动退出、反手、强平、混合或不可证明的退出中断连续。任何净盈亏都不能替代退出证据。普通账户按会话分开，自营账户还按轮次分开。

## 查看与展示

从个人档案查看摘要或进入成就收藏页，也可使用头像菜单。在收藏页通过头像切换用户时，直接打开所选用户的收藏页。选择“全部用户”时回到用户档案列表。回放菜单按实际会话归属打开，未归属会话提示选择具体档案。

收藏页每个系列显示一张卡，阶段记录包含条件阈值、规则版本、实际达成时间和记录时间。历史达成时间无法定位时显示同步提示。已删除来源的徽章和已保存摘要继续显示，跳转在可靠来源仍存在时提供。连续类分别显示进行中范围的当前数与历史最佳，历史记录的统计范围和证据缺口在详情中说明。

个人可选三个已解锁系列，按所选顺序展示。多阶段徽章的数字角标表示已解锁的最高阶段，单阶段徽章省略角标。悬停或键盘聚焦档案中的徽章时，提示显示对应成就的解锁条件。通知按档案确认浏览器回执，合并同批解锁或历史补算的记录。成就提示与经验获取共用头像下方的提示样式，显示 5 秒后自动消失，同时出现时纵向排列。网页全屏中由可见的用户入口接收通知。

## 历史补算与校验

直接打开 `/admin` 或 `/admin/achievements`。普通导航不显示维护入口；路由沿用项目无登录设计。

1. 选择用户范围与指标，运行预检查。服务器固定用户和实时证据水位，分批计算预计新增和覆盖缺口。预检查保存任务与暂存进度，不写已发布进度、徽章或原业务数据。
2. 检查预计变更，在详情中点击启动。后台追平预检查后新增的证据，再按用户原子切换所选指标。关闭页面后继续处理，已开始的任务在服务重启后按数据库游标继续。
3. 需要重新验证时创建校验计划。校验使用新进度代际，保留此前已授予的阶段；完成切换后回收已退休进度。补算或校验验证出同一规则、同一阈值的更早达成记录时，更新达成时间与来源，保留原记录时间且不重复通知。已失败任务可在详情中重试同一计划，无法确认提交结果的任务保留核对状态。
4. 未启动的计划可从详情放弃。新的预检查会释放可安全放弃的过期冲突计划，后台分批回收暂存进度并保留任务记录及已发布结果。

历史累计读取已结算成长事实。历史连续还需要与稳定周期身份对应的完整成交、可信的执行先后以及持仓数量链。缺失明细、同源柱执行顺序无法证实和已删除来源均会形成覆盖缺口。升级时已开仓的旧周期可核对持仓期间已保存的成交。补算与校验也可依据完整成交补足已结算周期的未知退出证据，仍有疑点时保留缺口。

## 实现与运维

- [目录与指标指纹](../../lib/achievements/catalog.ts)集中维护系列、阶段及证据版本。相同指标共享进度；已获阶段的阈值快照与规则指纹随奖章保存。
- [原子捕获](../../lib/user-growth/settlement.ts)、[退出累积](../../lib/paper-trading/persist.ts)和[证据校验](../../lib/achievements/evidence.ts)沿用既有业务事务，新增全局递增消费索引。
- [后台执行](../../lib/achievements/runtime.ts)优先处理新增事实，再处理历史批次。历史任务结合内存、事件循环延迟与现有重任务状态让出资源。使用单个 SQLite 运行槽、短批次及事务回执。使用 `better-sqlite3` 时，成就后台连接的 SQLite 写锁等待为 100 毫秒，批次事务时限为 1 秒。
- 结构变更从[升级指南](../operations/upgrade.md#当前入口)进入。迁移初始化结构及同步状态，首次历史计算仍由维护页确认启动。

读取 API 位于 `/api/users/{userId}/achievements`，展示偏好写入 `/api/users/{userId}/achievement-showcase`。维护任务与只读分页由 `/api/admin/achievements` 下的 API 提供。GET 只读，写入使用同源 JSON 请求。

实施方案与七项产品确认见[设计方案](achievements-design.md#19-已确认产品选择与发布标准)。目标服务器的 2 vCPU / 2 GiB 性能门槛仍需在目标或等价受限环境实测。
