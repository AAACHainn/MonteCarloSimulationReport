## 1. 产品目标与范围

为本人和朋友提供可随意切换的练习档案，记录各自的回放、交易、复盘和成长。小境界通过持续练习获得经验升级；大境界还须完成交易成果要求，使长期练习具有可见的正向反馈。

### 1.1 已确认的原则

- 无需登录，没有密码、角色权限、访问控制或多租户隔离。任何使用者都可以选择任意用户，查看其数据。
- 可以不创建用户，继续按当前方式使用全部数据。
- 本期个人归属仅覆盖 K 线回放及其交易、复盘和自营账户成果；独立交易日志、交易数据集、蒙特卡洛报告等暂不增加个人归属。
- 浏览器记住当前用户；用户档案、归属和成长数据保存在平台数据库，不只存在浏览器。
- 经验必须来自系统能记录的操作或结果；在线时长、观看图表、单纯推进 K 线均不发经验。
- 复盘经验只来自逐笔复盘。同一笔交易首次完成复盘奖励一次，再次编辑不重复奖励。
- 自营账户通过考核、成功出金同时纳入经验设计及大境界考核。
- 接受任意自营模板，不指定考核模板，不按公司或模板设置资格白名单。
- 删除原会话不影响已结算的经验及已累计的突破条件；这些数据独立保存在用户档案中。
- 三个月是基于每天约三小时、每天约 10～20 笔交易的难度设计目标，不是时间限制。经验和突破条件满足后即可突破。

### 1.2 不在本期增加的内容

登录、权限、真实转账、券商接入、排行榜、签到奖励、在线时长奖励、AI 复盘质量评分、整个会话复盘奖励、阶段复盘奖励，以及会话复盘次数门槛。

现有 AI 会话报告等能力继续使用，不因本方案增加经验或突破指标。

## 2. 用户选择与数据归属

### 2.1 默认入口与具体用户

推荐将默认入口显示为“全部用户”，辅助说明为“默认 · 全局数据”，避免“管理员”造成权限含义。

| 当前选择 | 默认查看范围 | 普通新建回放会话归属 | 个人成长 |
| --- | --- | --- | --- |
| 全部用户 | 所有用户及未归属会话 | 未归属 | 不产生个人经验 |
| 具体用户 | 该用户的会话及其交易、复盘 | 当前用户 | 符合资格的新训练会话参与成长 |

- “全部用户”是全局视图，不是一个与个人用户混合计算经验的实体。
- 行情源数据、行情导入与同步、自营模板、策略、交易理由、复盘模板、AI 配置仍为共享资源。
- 选择具体用户后，行情仍可共享使用；个人筛选作用于行情下的回放会话及其成果，不创建重复行情副本。
- 从全局视图或已有链接打开其他人的会话仍然允许，不以用户筛选拒绝访问。进入具体归属用户的会话时，如当前选择与归属不同，先弹窗说明归属者；确认才切为归属用户并进入，取消不改变选择或启动回放。未归属会话保持原选择。该确认是进入流程，不是登录或权限校验。
- 个人数据页应显示当前查看对象，避免将“当前选择用户”误当作登录身份。

### 2.2 浏览器记忆与会话上下文

- 推荐浏览器保存当前用户 ID；首次访问且没有保存的选择，或服务端已确认保存的用户 ID 无效时，回到“全部用户”。临时网络或列表加载失败应保留已知选择并提示重试，不能自动切到全局。浏览器存储不可用时，本次打开期间仍能选择和使用。
- 用户成长数据随平台数据库保存，换浏览器后只需重新选择用户。
- 普通新建会话时，如果当前选择的是具体用户，则归属该用户；如果当前选择的是“全部用户”，则保持未归属。创建提交时固定本次选择，服务端校验失败应返回错误，不得静默创建未归属会话。创建后交易、复盘、自营考核与出金始终归该会话的用户，不随右上角选择变化。
- 头像菜单先展示当前用户及操作；点击带切换图标的“切换用户”后，在同一弹层展示用户列表、返回按钮和折叠搜索。当前用户置顶，其后为“全部用户”；全局选中时“全部用户”置顶。
- K 线回放（含逐笔只读历史）隐藏“切换用户”入口。其他页面或标签的选择变化不转移已打开会话、不重建账户、不改变回放位置及在途操作归属。
- 已打开的回放工作区头像展示该会话归属者，详细归属和成长资格放在头像菜单中；顶部不额外常驻范围或归属说明。头像与原面包屑共行，不增加独立行。
- 无权限限制意味着任何人都能编辑已有会话；成果仍归会话所属用户，不另外记录“登录操作者”。

首版建议将“普通新建”“重新开始”和“重新考核”的继承规则明确区分，避免把创建新记录误解为自动切换归属。以下为本轮主审核定的设计建议，不是新增权限限制：

| 操作及来源 | 用户归属 | 成长资格与累计 |
| --- | --- | --- |
| 普通新建会话 | 本次创建时固定的当前选择 | 具体用户的训练会话参与成长；全局新建保持未归属 |
| 成长会话“重新开始” | 新会话继承原用户 | 继承成长资格，仅结算新会话新发生的成果，旧成果不复制 |
| 未归属会话“重新开始” | 新会话仍未归属 | 不参与成长，即使当前选择已变为某个用户也不自动归属 |
| 同会话内“重新考核” | 仍归原会话用户 | 继承原会话资格，新轮独立计算业务成果；已结算旧成果保留 |

实盘重演派生会话继续遵守不参与成长的建议范围。“重新开始”前在原确认流程中说明继承的用户及资格，不另设确认链；当前选择不同或为全局也不改变上述继承关系。

### 2.3 用户资料的首版建议

- 创建时填写昵称并选择头像；初始为凡人（累计获得 100 经验后晋升炼气一层）、0 经验。
- 支持修改昵称和头像，使用稳定用户 ID 关联记录，改名不改变归属或累计数据。
- 昵称推荐去除首尾空白后保持唯一，长度与错误文案在开发时按项目校验方式集中定义。
- 首版不增加用户档案物理删除和已归属会话跨用户转移入口，避免扩展本轮范围；后续如需增加，再定义对累计成果的处理。

## 3. 旧会话与归属边界

不提供事后归属旧会话、批量认领或跨用户转移入口。旧的未归属会话保持未归属，在“全部用户”范围查看；选择具体用户后普通新建训练会话，才开始该用户的成长记录。

会话仅保存用户 ID 与成长资格，不保存历史归属来源或归属时间。重新开始继承原会话用户和资格，重新考核不改变归属；不因当前选择变化而给旧会话补归属或补经验。未归属和实盘重演仍排除个人成长。

## 4. 成长资格与计数单位

### 4.1 首版参与范围

建议只让选择具体用户后新建的模拟训练会话参与成长，默认模拟账户与自营练习账户都适用。实盘重演仍可归属和查看，但不发成长经验，不贡献突破条件，以保持其可回退、纠错的现有用途。

从原会话派生的“重新开始”及同会话“重新考核”按第 2.2 节的继承建议处理，不重新读取浏览器当前选择来决定成长资格。

未归属及实盘重演的保存行为均不能意外触发成长结算。归档本身不改变原有成长资格，符合资格的归档训练会话仍可在补写逐笔复盘时结算一次奖励。

### 4.2 “交易”与“逐笔复盘”使用不同的既有业务单位

| 指标 | 计数单位 | 边界 |
| --- | --- | --- |
| 完成交易经验、累计完成交易量 | 完整持仓周期 | 从净持仓为空到再次为空；加减仓或日志拆行不增加周期数量，持续反手沿用现有周期规则 |
| 逐笔复盘经验、累计完成复盘量 | 现有逐笔交易日志中的一笔交易 | 用户实际编辑的日志记录使用稳定业务身份去重；同一笔交易只奖励一次 |
| 考核通过次数 | 会话 ID + 账户轮次 | 同一轮考核最多成功一次，不按当前界面显示阶段反复累计 |
| 成功出金次数与实得 | 成功出金流水 | 每条独立成功流水计一次；不同时消费其对应账户事件再计一遍 |

现有 FIFO 日志可能把一个完整持仓周期拆成多笔可独立复盘的交易。这些交易各自首次完成复盘可以各奖励一次，但不能因此多发完整持仓周期的交易经验。复盘去重不能使用会随排序、筛选或轮次变化的显示编号。

开发时应复用现有交易身份、轮次和日志映射；如使用 `logicalKey`，须连同会话和轮次作用域形成稳定身份，不把 projection ID 或显示编号作为唯一业务身份。不为旧会话补造身份或补发经验。

## 5. 经验获取

### 5.1 V1 建议参数

下列数值沿用讨论草案，属于首版建议参数；逐笔复盘一次性奖励、历史不补发及删除不扣回等原则为已确认要求。

| 来源 | 经验 | 结算时机 | 去重边界 |
| --- | --- | --- | --- |
| 完成一个完整持仓周期 | +5 | 已产生有效完成结果并成功保存 | 每个周期一次 |
| 首次完成一笔逐笔复盘 | +10 | 用户编辑后明确保存成功 | 每笔日志交易一次 |
| 自营考核通过 | +100 | 正式进入出金阶段并成功保存 | 每个账户轮次一次 |
| 自营本轮首次成功出金 | +200 | 本轮第一条成功出金流水保存 | 每个账户轮次一次 |

- 交易盈亏不影响基础经验，亏损不倒扣经验；自营奖励可与交易、复盘奖励叠加。
- 自营后续出金仍计入突破次数及金额，但首版不再次发该轮首次出金经验。
- 不发创建用户、创建会话、创建账户、重新考核、恢复播放、纯推进、观察或在线时长经验。
- 不设置签到、连续天数、每日硬性经验上限或断签惩罚。

### 5.2 逐笔复盘的最终规则

1. 用户在现有逐笔复盘编辑器中编辑内容并点击保存。
2. 保存成功，且去除首尾空白后内容非空，视为本次完成；不额外要求 20 字或评分达标。
3. 该笔交易尚无复盘奖励时，增加一次复盘经验和一次累计完成复盘数。
4. 同一笔交易以后再次编辑、清空重填、重复保存或换浏览器保存，均不重复奖励。
5. 保存失败、只有空白、只修改 Setup / 理由、只打开编辑器或只在本地输入，均不结算复盘奖励。
6. 系统自动预填计划、自动生成 AI 草稿或生成会话报告不算完成逐笔复盘；用户采用或编辑逐笔内容并明确保存后，按同一规则结算。

服务端须在保存事务内判断首次完成：请求明确保存逐笔复盘，保存后的内容非空，且相比事务内校验的原内容发生实际文字变化，或存在可验证的显式 AI 草稿采用来源。比较时去除首尾空白，仅增删首尾空白不算新的复盘完成；不依赖客户端传来的“已编辑”布尔值，也不使用页面加载时的旧文本直接结算。

显式采用 AI 草稿并点击保存，按既有采用来源记录验证，可以作为完成行为；不能仅因采用文本与已有文字相同而一概拒绝。直接重存系统自动预填且未经编辑或显式采用的原内容不奖励。内容保存、首次奖励去重与累计应一致，保存冲突不发经验；已经奖励的请求重试只返回原结算结果。已结算的奖励不因复盘后来被清空而撤回。

不新增会话总结奖励、阶段复盘、覆盖区间选择、非重叠交易区间检查，或强制填写会话总结的流程。

## 6. 境界、经验与突破

### 6.1 境界结构

境界分为凡人期、炼气期、筑基期、金丹期、元婴期、化神期。凡人期不分层，新用户从凡人期、0 经验开始，累计获得 100 经验后自动晋升炼气一层，无额外突破条件；炼气期及后续境界每个境界规划 12 层。统一使用“炼气”，界面可显示“炼气一层”“炼气十二层”。

首版建议开放凡人期、炼气一层至十二层，以及突破后的筑基一层。筑基二层及以上标记“待开放”，不预设未讨论的升级或突破数值。到筑基一层后继续记录经验和成果，不清零，也不按炼气经验公式自动升级后续境界。

### 6.2 凡人至炼气经验表：V1 建议参数

累计经验为终身累计值。升级不扣除累计经验，界面按当前阶段或层级区间展示进度。新增凡人期的 100 经验后，原炼气各段所需经验不变，累计经验门槛统一增加 100；表中分层均指炼气期。

| 升级阶段 | 本段经验 | 到达后累计经验 |
| --- | ---: | ---: |
| 凡人 → 炼气一层 | 100 | 100 |
| 一层 → 二层 | 300 | 400 |
| 二层 → 三层 | 450 | 850 |
| 三层 → 四层 | 600 | 1,450 |
| 四层 → 五层 | 750 | 2,200 |
| 五层 → 六层 | 900 | 3,100 |
| 六层 → 七层 | 1,050 | 4,150 |
| 七层 → 八层 | 1,200 | 5,350 |
| 八层 → 九层 | 1,500 | 6,850 |
| 九层 → 十层 | 1,800 | 8,650 |
| 十层 → 十一层 | 2,250 | 10,900 |
| 十一层 → 十二层 | 2,700 | 13,600 |
| 十二层突破准备 | 4,500 | 18,100 |

凡人期达到 100 经验自动晋升炼气一层；同一大境界内按经验自动升级。单次奖励跨过多个经验门槛时，按累计经验到达对应的已开放层级，不丢失超出部分。十二层显示“突破准备”，达到 18,100 经验后继续累计经验，其他成果不足时显示具体缺口。

### 6.3 炼气突破筑基

以下全部满足后可突破；前三项沿用本轮数值草案，自营成果及无时间限制为用户明确要求。

| 类别 | 指标 | 门槛 | 确认状态 |
| --- | --- | ---: | --- |
| 经验 | 终身累计经验 | ≥18,100 | V1 建议参数 |
| 练习积累 | 完成持仓周期 | ≥1,200 个 | V1 建议参数 |
| 复盘积累 | 首次完成逐笔复盘的交易 | ≥600 笔 | V1 建议参数 |
| 自营成果 | 通过考核 | ≥20 次 | 已确认 |
| 自营成果 | 成功出金 | ≥10 次 | 已确认 |
| 自营成果 | 分成后累计实得 | ≥100,000 USDT | 已确认 |

- 没有满三个月、90 个有效日、每天三小时、会话数量或会话复盘数量门槛。
- 自营模板任意，无指定模板、公司、账户规模或隐含难度要求。
- 不要求每个通过考核的账户都出金，不要求 10 个不同账户或 10 个不同轮次出金。
- 不要求先将出金账户做失败，也不以“重新考核”操作本身增加成功次数。
- 不额外叠加曾讨论的“单会话 +3% 收益、最大回撤 5%”考核；自营通过及出金沿用原账户规则。
- 成果可在凡人期或炼气任何层取得，无需经验满后再开启专门考核。
- 推荐全部条件满足时提供“突破筑基”按钮；服务端复核并一次性记录突破。点击失败保留进度，重复提交不重复突破。
- 不因后续账户失败、会话归档或删除而降级、撤销突破或减少已结算累计值。

### 6.4 自营成果的具体口径

- 自动和手动晋级都认可，以原账户真实保存的考核通过结果为准；预览显示达标但未晋级不算通过。
- 不同会话内创建的账户、同一会话内不同账户轮次的成功结果均累计。
- 同一轮可持续多次出金，每条独立成功流水都增加一次突破出金次数，金额按对应流水实得累计。
- 金额使用分成后的 `received`，不使用申请额 `amount`，不扣当前仅记录的账号购买和激活费用。
- 成长金额只记录、累计与展示 USDT 实得，不提供“分币种实得”或其他币种金额记录；不把 USD 等其他币种默认视为 USDT，不做汇率折算。通过和成功出金次数仍按相同资格累计，本轮不改变任意模板原则。现有账户的币种设置是否取消另行实施，不在第一阶段修改。
- 沿用当前金额精度，累计应避免浮点误差；若按现有两位小数使用最小单位存储，100,000 USDT 对应 10,000,000 个最小单位。不得仅因界面四舍五入看起来达标就提前突破。

示例：用户在不同会话通过 12 次，在一个长期会话的不同轮次通过 8 次，累计通过 20 次；其中一轮持续出金 10 次、累计实得 100,000 USDT，即满足三个自营成果条件。无需主动结束该出金账户。若经验、交易量或逐笔复盘数不足，仍须补齐相应条件。

### 6.5 三个月目标的校准说明

三个月是估算目标，不能承诺所有人至少练满三个月。每天三小时不是系统计量条件，也不等于固定交易或复盘数量。

简化按每天 15 个完成周期、10 笔首次逐笔复盘估算，每天基础经验为 175。20 次考核通过带来 2,000 经验；10 次成功出金如来自同一轮，首次出金经验为 200，如分别来自 10 轮则为 2,000。达到 18,100 经验约需 81～91 个这样的练习日，且仍须满足所有成果门槛。

该估算没有会话复盘经验，假设成果均来自具备成长资格的会话，且不存在更多额外奖励。高频练习或大量补复盘可以更快达到经验；100,000 USDT 实得及其他条件也可能需要更久。若实际使用节奏明显偏离目标，后续单独调整未来规则，不能静默改写已结算经验或撤销已取得境界。

## 7. 成长记录独立持久化

### 7.1 已结算成果不随会话生命周期变化

用户累计经验、完成交易数、首次完成复盘数、考核通过数、成功出金数和 USDT 累计实得，应有独立的成长记录与累计投影。

- 不通过实时统计当前还存在的会话、交易或出金表来计算终身成长值。
- 删除会话、数据集及其原交易记录，不级联删除用户成长记录。用户已经达到的条件仍保留。
- 原来源可保存为普通标识或可置空关联，不得使用向源会话的级联删除关系保存唯一成长证据。
- 归档、失败、重新考核不会扣回已结算值。新轮成功可以新增成果，但不能重复结算旧轮。
- 统计页明确区分“成长累计（含已删除来源）”与“当前会话统计”，两者数值不同是预期行为。

### 7.2 推荐记录的事实

| 事实 | 建议保存内容 |
| --- | --- |
| 用户档案 | 稳定 ID、昵称、头像来源、创建时间 |
| 会话归属与资格 | 用户 ID、是否参与成长 |
| 成长事实 / 流水 | 用户 ID、类型、稳定来源键、会话 / 轮次摘要、发生和结算时间、经验变化、计数变化、USDT 实得、规则版本 |
| 用户成长累计 | 累计经验、各项累计次数、USDT 实得、当前境界、层级和并发版本 |
| 境界突破记录 | 用户 ID、突破前后境界、当时满足的指标快照及规则版本 |

此表描述数据职责，不规定必须新增同名表或冗余保存完整复盘正文。完整 Prisma 结构和 API 在开发阶段设计。

成长事实保存结算当时实际发放的经验、各计数增量、USDT 实得数值，以及稳定来源键和必要摘要；规则版本用于解释当时的口径。重建用户累计投影时重放这些已经结算的数值，不拿最新规则重新计算历史奖励，也不依赖源会话仍存在。历史记录的规则版本、金额精度及摘要应能独立解释原结果。

### 7.3 幂等与原子性要求

- 稳定来源唯一键在删除原会话后仍保留，不能因来源删除而失去去重能力。
- 成长事实及对应累计更新必须一致；原业务失败不产生经验，重试只能结算一次。
- 晋级事件和出金流水在原系统已经存在。成长系统消费已成功结果，不在组件中重新判断账户是否通过，也不再扣一次资金。
- 考核通过以会话 + 轮次去重；出金按流水去重；首次出金额外按会话 + 轮次去重发一次经验。
- 一条出金流水既更新成功次数和实得，又可能产生首次出金经验，这些更新必须保持一致。
- 源结果保存与可持久恢复的成长事实建立需确保一致，不能依赖页面弹出成功提示后再请求发经验，也不能因稍后删除源会话丢失尚待处理的事实。
- 用户归属以实际业务会话为准，不能信任客户端随请求传来的任意用户 ID 来结算。
- 已删除来源显示“原会话已删除”，保留必要摘要；不生成指向其他同名会话或重排交易编号的错误链接。

## 8. 页面与交互设计

本节为可迭代的首版视觉与交互提案；用户已允许本模块局部突破现有 UI 规范，但具体颜色、布局和动效尚未逐项定稿。所有成长数值、资格及累计口径仍以第 3～7 节为准，示例数字仅用于说明界面，不新增奖励、任务或突破条件。

### 8.1 视觉概念：一份可持续积累的修行档案

采用“浅纸、墨字、细线、玉色标记”的档案语言。打开页面先看到一个具体的人及其当前境界，再看到距离下一步还差什么，最后看到每次积累从何而来。修仙氛围集中在头像、境界字样与细线轨迹；交易结果、会话和资金仍使用工作台的清楚表述。

- **底与面：** 沿用全局浅灰背景和白色内容表面；档案身份区可使用极浅暖白，边缘以一条低对比度远山轮廓收束。纹样只在右侧留白出现，不铺在文字、数据或控件背后，不增加独立大横幅。
- **墨与玉：** Slate 深色承担标题与数据；蓝色继续表示可点击操作、选中和导航。局部玉色只用于境界标记及经验轨迹，哑金只用于突破可用或已达成境界的细小标记。盈亏、成功、警告和错误仍沿用既有语义色；未满足的成长条件用中性文字，不做亏损红或告警黄。
- **字与数：** 昵称为页面一级标题，沿用 `text-3xl`；境界用 `text-2xl`，可试用本地中文宋体回退形成轻微书卷感。其余正文、表单及数字沿用现有字体，金额和计数使用 `tabular-nums`。不使用书法字呈现姓名、按钮或关键数字，不依赖外部字体加载。
- **形与留白：** 保留现有控件和卡片圆角、轻边框；头像是主要圆形元素。使用横向分隔线和成组行组织指标，避免把每个数值包装成独立卡片。境界不用大型发光徽章，经验不使用围绕头像的进度环，避免与身份、完成比例相互混淆。
- **主题集中维护：** 新的纸色、玉色、哑金及装饰资源应定义为用户模块的语义 token / 主题变体，先验证对比度，再用于身份和成长展示；禁止业务组件散落任意色值或改写全局颜色。

首版只保留一处远山线稿、一条境界轨迹和一处突破强调。人物插画不扩展成整页背景，页面无漂浮粒子、循环光效、音效或遮挡内容的庆祝层。

### 8.2 用户入口：明确选择、查看和会话归属

全局 Header 右侧仅显示 40px 圆形头像，不在触发点外露昵称、境界、矩形边框或下拉箭头；“全部用户”使用圆形中性群组图标。完整当前选择通过悬停标题、无障碍名称和打开菜单后的勾选项取得。此项依据第二阶段验收反馈调整，菜单仍支持用户切换。

头像弹层宽 320px，初始页展示当前选择或实际会话归属、资料入口与带双向箭头的“切换用户”。点击后在同一弹层显示用户列表、返回按钮和放大镜搜索；当前用户第一、全部用户第二，全局选中时全部用户第一。搜索默认折叠，列表独立滚动。键盘进入列表后聚焦返回；Escape 依次收起搜索、返回初级菜单、关闭弹层。

- 选择后关闭菜单，保存浏览器记忆。档案详情主动切换时跟随打开该档案；直接打开他人档案只改变查看对象。全局“用户档案”打开列表。
- 回放顶部头像与原面包屑共行，20px；该局部尺寸依据用户反馈，不增加身份行或常驻范围说明。回放菜单不提供切换用户；头像按会话实际归属显示，详细归属和成长资格在菜单内可见。无用户与未归属、加载/失败状态分别表述。
- 从全局或其他用户进入个人会话前确认归属，确认才自动选择归属者并进入；取消不改变选择或导航。直接 URL 同样在回放组件挂载前确认。未归属会话保持当前选择。这些是进入流程，不是权限。
- 列表暂时读取失败保留选择；确认用户失效才回全局。共享页面不改成个人数据，不扩大筛选。

普通新建会话表单在提交按钮上方明确显示“新会话归属：小明”或“未归属”；确认尚未创建任何用户时显示“未创建用户”，提交中锁定该次创建的选择。此处只解释创建归属；“重新开始”在原确认流程中展示第 2.2 节规定的继承归属与资格，不能由界面位置或当前头像推断。

### 8.3 档案页构图：身份、下一步、积累证据

保留现有标准页面容器，不另建全屏仙侠场景。面包屑为“用户档案 / 小明”，随后是一块开放式身份区，替代普通页中重复的“页面大标题 + 同名个人卡片”。根据第一阶段体验反馈，条件账页与最近成长记录改为上下排列、间距 24px；收起条件或切换境界时不再出现并排区块高度悬殊的问题，不用空白强行补齐高度。

用户档案 / 小明
┌────────────────────────────────────────────────────────────┐
│ [头像] 小明                               编辑资料          │
│        炼气十二层 · 突破准备                               │
│        累计经验 16,500                                       │
│        本段 2,900 / 4,500  ━━━━━━━━━━━────  还需 1,600 经验   │
│        凡人 ─ 炼气 · 一 … 十二 ─ 筑基     后续境界待开放    │
└────────────────────────────────────────────────────────────┘
┌────────────────────────────────────────────────────────────┐
│ 筑基条件                                  已满足 3 / 6     │
│ 练习积累：累计经验 / 完成持仓周期 / 首次逐笔复盘             │
│ 自营成果：考核通过 / 成功出金 / USDT 实得                    │

└────────────────────────────────────────────────────────────┘
┌────────────────────────────────────────────────────────────┐
│ 最近成长记录                              共 N 条记录       │

- **身份区：** 建议 80px 头像；姓名、境界和经验形成三级层级。编辑资料为低强调度操作；会话列表直接位于下方，不提供仅滚动定位的“查看回放会话”按钮。条件全部满足时，“突破筑基”为身份区唯一主操作。
- **经验：** 主要进度条表达本层区间，累计经验单列，不能把本段与终身经验混成一个分数。例如累计 16,500 时，本段为 `(16,500 − 13,600) / 4,500 = 2,900 / 4,500`。始终显示文本数值和下一目标，百分比不是唯一信息。
- **境界轨迹：** 低高度横向线标示凡人、炼气、筑基。炼气状态可展开为 12 个等距小刻度，当前层显示完整标签；其作用是位置索引，不表示各层经验相同。未来境界合并为“后续境界待开放”，不画长串灰色锁，也不暗示完成当前任务就能解锁。
- **条件账页：** 单一容器中分“练习积累”“自营成果”两组，固定六行，数字右对齐，状态显示“已满足”或具体差额。行内可有细进度线，但真实值超出门槛仍完整显示，进度填充最多 100%。标题的“已满足 3/6”仅为条件数量，不是综合突破百分比。
- **数据口径：** 条件区注明“成长累计，含已删除来源”。指标本身直接复用成长累计，不再在上方重复六张 KPI 卡。仅展示和记录 USDT 实得，不增加分币种详情。
- **下方会话区：** 展示该用户当前存在的回放会话及其基本信息、模式、账户类别和成长资格；沿用既有列表与打开方式，必要时分页。历史表现如需展示，放在会话范围中并注明口径，不与终身成长计数并列成一组。

凡人期的首屏优先显示“累计 100 经验进入炼气一层”及下一步说明；筑基条件可默认收起为“查看筑基条件”，展开后仍完整可读。进入炼气后默认展开条件，避免临近十二层才第一次发现成果门槛。下方成长记录为空时显示“完成符合资格的交易或首次逐笔复盘后，记录会出现在这里”，不显示虚构示例流水。

### 8.4 境界状态与突破交互

| 状态 | 主展示与下一步 | 操作及反馈 |
| --- | --- | --- |
| 凡人，累计不足 100 | 凡人；当前经验 / 100；还需多少经验 | 无突破按钮，达到 100 后自动显示炼气一层 |
| 炼气一至十一层 | 当前层、本段经验与下一层 | 自动升级；单次跨多层只反馈最终到达层级 |
| 炼气十二层，经验不足 | 突破准备；本段经验 / 4,500 | 显示经验及其他条件缺口，不显示倒计时 |
| 经验满足，其他条件不足 | “经验已满足”；累计经验继续增长 | 条件区列明尚缺项；不制造“领取”或额外考核步骤 |
| 六项全部满足 | “可突破筑基”，细哑金标记 | 启用“突破筑基”；点击后提交服务端复核，不再增加二次确认或虚拟成功概率 |
| 突破提交中 / 失败 | 保留原境界与全部条件 | 按钮显示“正在突破”；失败就地说明并可重试，不清零进度 |
| 筑基一层 | 筑基一层、达成记录、终身累计经验 | 原条件摘要为“已突破”，默认收起；显示“后续层级待开放，经验与成果继续累计”，不画无目标的升级进度条 |

条件未满足时如展示禁用的突破按钮，其旁必须有可读缺口；条件区域始终可展开查看，不用禁用按钮的 Tooltip 承载唯一解释。条件查询失败时显示“暂时无法确认突破条件”，不能显示零进度或误判为未满足。

突破成功后在原身份区完成一次短暂的边线强调和境界文字替换，并在成长记录中留下可查询的达成记录。建议动效 300～500ms，普通进度变化 150～200ms；开启减少动画时直接切换并保留文字状态。不自动播放人物动画、不强制弹窗、不夺取键盘焦点；按钮消失时将焦点合理落在新境界标题或对应状态，不落回页面顶部。

### 8.5 成长记录

**成长记录。** 档案中默认展示最近 5 条，并显示历史记录总数。“查看全部记录”在档案内打开分页窗口，每页 20 条；历史记录完整保留，不按最近条数截断或删除。几千条历史也按页读取，不提供一次全量展开。正式接入时使用服务端有上限的分页查询，按结算时间及稳定 ID 倒序，在并发新增时保持分页边界稳定；浏览器只接收最近 5 条与当前页，不预加载全量历史。不另建奖励领取页。每条包含事件名称、经验变化、相关计数或实得变化、结算时间与来源摘要；“成功出金”即使本次经验为 0，也显示其出金次数和实得贡献。时间以实际结算时间为主，回放交易时间在来源详情中另标，避免把历史行情日期误认为奖励发放日期。

一笔事实对应一条可解释记录，例如“成功出金 · 次数 +1 · 实得 900 USDT · 本轮首次出金经验 +200”，不拆成多条仿佛重复出金的流水。现存来源可打开对应会话 / 轮次 / 交易；已删除来源保留摘要并显示“原会话已删除”，不提供死链接。自动升级、突破反馈可引用对应事实，但不能把展示提示重复写成第二次经验奖励。

### 8.6 创建资料与头像融合

创建与编辑复用同一资料表单，放在标准 `Dialog` 中：左侧昵称字段和说明，右侧头像预览；宽度不足时上下排列。创建默认显示凡人及 0 经验，编辑显示当前真实境界，不能编辑经验或境界。

头像在档案中建议 80px、全局入口 40px、列表 32px，均采用统一圆形裁切、细中性边框。预制图以人物头肩为主，五官居中、背景简洁；缩小到 32px 仍可辨认。上传图使用相同容器和裁切方式，保留用户原图色彩，不强加仙侠滤镜。境界标记放在头像旁的文字区，不叠在脸部，也不随境界替换头像。

选择区分“预制头像”“上传图片”，预制选项以清晰选中边框与勾选表示，键盘也可选；上传按照第 9 节的格式、大小与裁切建议执行。裁切提供预览和可键盘操作的缩放 / 位置调整，不能只有鼠标拖拽。未加载、图片损坏时使用中性人物占位及昵称，不伪造新的头像素材。

保存成功后同步入口、档案和列表头像；上传中或保存中显示局部进度，失败保留旧资料及本地编辑内容。取消不修改已保存资料，不因预览上传成功就提前替换当前头像。文案使用“创建用户”“编辑资料”“保存资料”，避免“注册”“登录”“账号安全”等与本期范围不符的表述。

### 8.7 原操作中的经验反馈

逐笔复盘继续使用既有编辑器和保存动作。首次成功结算的就地状态为“复盘已保存，经验 +10”；已有奖励再次保存仅提示“复盘已保存”，详情可显示“本笔复盘经验已获得”。未归属或实盘重演仍可保存，按实际资格给出简短说明，不禁用保存，不显示零经验失败告警。

回放工作区中的完成交易、考核通过与出金反馈优先附在原操作结果中，不为每笔结果新增浮动卡片。连续推进产生多笔成长时，可将同一次成功返回的增量合并为一条简短状态；明细全部保留在成长记录中。提示必须注明实际会话所属用户，尤其当前选择已切到另一个人时，不能让用户误认为经验进入当前头像。

自动升级轻量播报“已晋升炼气六层”，不遮挡图表、下单或复盘编辑器，不主动暂停播放。反馈只根据已结算结果出现；原保存成功但成长状态尚待确认时，先保留“已保存”，后续依据持久化结果更新，不播放未经确认的经验增长。恢复或刷新取得已存在记录时不重播整段奖励动画。

所有异步区域保留自身布局，局部处理加载、空、成功和失败。切换档案或用户后，旧请求返回不能覆盖新查看对象；失败保留草稿、选择和可用旧值，并明确旧值尚未刷新，不将错误当作 0 经验。

### 8.8 桌面适配与可访问性

- 在 1440px 与 1920px 桌面沿用 `max-w-7xl`，不为填满大屏放大头像或装饰。各桌面宽度均依次纵向排列身份、条件、成长记录、会话，避免并排区块高度差；成长记录窗口内部滚动，分页信息与操作保持可见。窄窗口按内容自然换行，不能靠压缩金额或隐藏条件维持布局。
- 短高度桌面允许整页纵向滚动，身份区不固定占满首屏。菜单与弹窗限于视口内部，表格独立横向滚动，主体不产生横向滚动。顶部工具栏空间不足时先省略入口中的境界短文案，再把会话归属移至会话标题下一行，不能隐藏实际归属。
- 主要操作至少 40px；回放高频工具区可沿用 32 / 36px。菜单支持键盘进入、选择和 Escape 返回触发点；搜索有可见标签或适当的无障碍名称；头像旁已有昵称时避免重复播报图片描述。
- 经验条提供当前值、区间最大值及文本替代；境界轨迹提供“当前炼气第六层，共十二层”的文本，不依赖十二个点的颜色。条件满足同时使用勾选和文字，不能只改变颜色。
- 本段经验、累计经验、门槛和金额使用真实可读对比度；普通文本建议至少 4.5:1，必要图形和控件边界至少 3:1。12px 只用于辅助信息，不承载唯一金额、归属或操作解释。
- 保存与升级结果用 `role="status"` / `aria-live="polite"` 合并播报，批量推进不逐条打断读屏；立即需要处理的错误使用 `role="alert"`。弹窗正确管理焦点、背景滚动及关闭行为，装饰线稿 `aria-hidden`，全部动画尊重减少动画偏好。

### 8.9 组件落地、局部例外与评审方式

基础交互优先复用 `Button`、`Dialog`、`ConfirmDialog`、`Input`、`Table`、`Alert`、`Badge`、Popover 与搜索组件；用户模块组合成档案身份区、境界轨迹、条件行、成长记录和用户选择器。主题样式集中在用户模块；基础控件不足的焦点、尺寸或状态能力在 `components/ui/` 中补齐，不复制一套按钮或弹窗。固定文案纳入 `lib/i18n.ts`，数值复用 `lib/format.ts`，实得明确显示币种。

本提案的局部例外为：身份区替代标准标题分隔结构、局部暖纸 / 玉色 / 哑金、境界字样的可选宋体，以及少量远山线稿与境界动效。原因是强化个人长期成长的辨识度；范围限于用户档案、成长展示和资料弹窗。全局与回放中的用户入口只采用紧凑身份元素，其他业务页面不使用整套主题。

后续 UI 评审先提供可比较的静态状态：全局入口、凡人空档案、炼气中段、十二层缺条件、可突破、筑基一层，以及当前选择与会话归属不一致和头像上传。先确认构图、信息密度与头像风格，再调整色彩、纹样和动效；视觉调整不改变奖励或条件规则。

以下为分阶段交付检查要求；实际执行结果与未验证内容以各阶段交付记录为准，不能把清单当作通过证据：

- [ ] 对照桌面 UI 规范检查标题、主操作、组件复用、数字及状态语义，并记录本节例外。
- [ ] 在 1280px、1440px、1920px 及短高度窗口检查布局、菜单、长昵称、大额金额和内部滚动。
- [ ] 对照原回放页面检查图表与下单区域未被侵占，切换器与会话归属不会混淆。
- [ ] 检查普通 HTTP、图片失败、保存失败、并发冲突、查询陈旧和已删除来源状态。
- [ ] 完成键盘、焦点、读屏状态、对比度及减少动画检查；确认装饰不承担唯一信息。
- [ ] 按用户反馈迭代视觉方案，确认主题样式未泄漏到其他页面；重复出现的主题控件集中抽象。

## 9. 头像

已确认同时支持预制头像及用户上传。

首版建议：

- 预制 8 个统一淡彩水墨画风的修仙人物头像，已由内置 imagegen 生成并优化为 512px WebP；资源与提示词见 [头像资源记录](user-growth-avatar-assets.md)。
- 头像不与境界绑定，不强制用户升级后换头像；境界信息单独显示。
- 上传支持 PNG、JPEG、WebP，建议不超过 5 MiB；预览后裁剪为正方形，统一圆形展示。
- 服务端独立核验实际 PNG/JPEG/WebP 格式、静态单帧、最多 5 MiB、每边 64～8,192px、总像素最多 2,400 万，按 EXIF 方向旋转、裁切并重新编码为 512×512 WebP，剥离上传元数据。不接受 SVG、GIF、外部图片 URL 或客户端指定的文件路径。
- 上传成功后再替换原头像，失败保留原头像；临时预览、取消操作不改资料。头像只在资料和切换入口使用，不成为新的内容分享功能。
- 上传文件与生成过程临时产物不提交 Git；正式预制资源在开发阶段按项目资源约定纳入交付。

数量、画风、上传大小和输出尺寸为设计建议，生成素材前可以单独调整，不影响核心需求定稿。

## 10. 兼容与后续实施边界

- 不修改现有撮合、费用、滑点、数量、OCO、交易关卡、源 K 推进或自营风控算法来计算成长。
- 用户筛选不是权限过滤；会话身份、projection、版本和轮次等现有写入校验继续保留。
- 行情导入、同步和全局资源不因用户切换复制或迁移；不能恢复完整行情接口。
- 后续数据结构变化须同步 Prisma 迁移和 `scripts/init-sqlite.mjs`，按[升级指南](../operations/upgrade.md)核对目标库并备份。本文不授权现在执行升级。
- 升级时原会话保持未归属，不创建虚拟管理员、不自动认领、不从历史数据补算成长，也不要求已有使用者先创建用户。
- 普通 HTTP / 局域网访问必须可用。浏览器 UUID 使用统一 `createUuid()`；不能直接依赖 `crypto.randomUUID` 或其他安全上下文 API。上传和裁剪亦须按能力检测及 HTTP 兼容方式设计。
- 成长结算放在独立业务模块，页面只展示结果，API 负责校验与调用。层级和阈值集中维护并记录规则版本，不在组件中复制。

## 11. 后续开发验收场景

以下是各阶段的验收要求；实际已完成范围、应用测试和浏览器结果见对应阶段交付记录。

### 用户与会话归属

- 不创建用户时，现有入口、全部数据及使用流程保持可用。
- 创建和切换用户无需登录，浏览器刷新保留选择，换浏览器可重新选择同一档案。
- 临时加载失败保留当前选择；创建校验失败不能静默变成未归属。仅确认保存的用户 ID 无效后回到全局。
- 可以打开其他用户的已有链接；用户切换不重分配当前会话或在途操作。
- “重新开始”及“重新考核”按继承表处理，覆盖原会话属于成长、未归属，以及当前选择不同或全局的情形；不得复制旧经验。
- 档案不提供事后归属入口，旧未归属会话仅在全部用户范围可见。

### 逐笔复盘和经验

- 合格训练会话完成一个持仓周期只发一次基础经验；部分平仓或日志拆行不重复发周期经验。
- 一笔日志交易首次编辑并保存非空复盘发一次经验、累计一次复盘；之后编辑、清空重填、重试或双标签并发都不重复。
- 同一周期中不同可独立编辑的日志交易分别复盘时，按各自稳定身份奖励，不与周期经验去重混淆。
- 保存失败、仅本地编辑、仅改 Setup / 理由、空白内容、系统自动预填及 AI 未采用草稿不发奖励。
- 仅改首尾空白不触发首次完成；显式采用来源须经服务端验证，不因与已有文本相同而一概拒绝。并发、保存冲突和重试不重复结算。
- 未归属、实盘重演不参与成长；整个会话报告或总结不贡献复盘经验与次数。

### 自营成果与突破

- 跨会话、跨轮次累计考核成功；同一轮手动 / 自动结果或重试只累计一次。
- 同一轮多次成功出金全部累计突破次数及实得，但仅首次产生该轮出金经验。
- 提款预览、失败申请、回滚和重复请求不新增成果；流水和关联账户事件不会重复计数。
- 恰好通过 20 次、出金 10 次、实得 100,000 USDT 时三个自营指标达标；少一项仍不可突破。
- 申请额达 100,000 而实得不足、其他币种金额、显示四舍五入均不能代替 USDT 实得门槛。
- 任何模板均可；不隐含要求不同公司、不同模板、不同出金轮次或先失败再重新考核。
- 所有条件满足，即使不足三个月也允许突破；练满三个月但条件不足仍不能突破。
- 不存在会话复盘、阶段复盘、90 个练习日或每日三小时的隐藏条件。
- 突破重复请求只保存一次；达到筑基一层后仍累计经验和成果，但不自动进入未开放层级。

### 删除与兼容

- 删除来源会话及其关联数据后，所有已结算经验、次数、实得和已达到的境界保留。
- 删除后查询、重建用户累计投影及去重仍依据独立成长事实，不回查已不存在的会话重算为零。
- 更换后续规则版本后，重建仍按历史已结算增量复原累计，不使用新参数重算原奖励。
- 默认账户和自营账户的原交易结果、账户轮次、关卡、回放推进与删除行为不因成长系统改变。
- 按桌面 UI 检查清单验证交互；在 `crypto.randomUUID` 不可用的普通 HTTP 环境验证用户创建、头像上传、复盘及突破相关流程。

## 12. 讨论中已撤回的方案

为避免开发误用早期回复，以下内容不属于当前设计：

- 2,300 经验的快速筑基方案。
- 纯观察、在线时长或单纯推进 K 线奖励。
- 整个会话复盘或阶段复盘 +30 经验、12 份会话总结门槛、10 笔覆盖范围与非重叠复盘区间要求。
- 逐笔复盘至少 20 字或 AI 质量评分。
- 必须三个不同轮次各自通过考核并首次出金的条件。
- 必须指定模板、指定公司或事先开启独立突破考核会话。
- 满三个月、90 个有效练习日等时间门槛。
- 删除来源会话后扣经验、减少已累计条件或撤销已取得境界。

后续开发以本文的已确认要求为边界；数值和交互建议如需调整，应明确更新版本与说明，不能复活上述撤回流程。
