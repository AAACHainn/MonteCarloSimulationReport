# 用户成长分阶段方案：历史摘要

> 文档状态：设计与计划。适用范围：2026-10-25 至 2026-10-26 的五阶段方案，已有实施记录；阶段确认不作为当前待办或操作授权。
> 当前规范：[用户档案与成长](user-growth-design.md)、[用户资金](user-wallet-transfers-progress.md#当前规则)。

## 分阶段的原因

当时先验证界面方向，再固定用户归属，随后接入日常经验与自营成果，最后完成头像和整体验证，避免把预览数据、尚未接入的奖励或临界测试样例混入真实用户数据。该方案已实施，不再保留逐阶段启动、手动验收和“交付后等待继续”的执行模板。

## 保留的设计决策

- 预览与持久化使用相同展示组件，演示控制不进入正式奖励入口。
- 独立成长事实先建基础，再接入奖励；接入前完成的交易不补算，删除来源不删除已结算事实。
- 奖励数值由首版建议形成并记录规则版本，历史重建汇总已存 delta，不用新参数重算旧奖励。当前值在成长规范和代码维护，本计划不重复列数值表。
- 各阶段使用独立副本和合成临界样例，避免要求真实用户反复考核、出金或删除来源来验收。
- 早期历史会话认领及其专用字段已于 2026-10-26 取消；阶段记录中该功能的截图与测试仅证明当时实现。
