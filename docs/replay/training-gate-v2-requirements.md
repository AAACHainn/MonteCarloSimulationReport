# 交易关卡深化设计

> 文档状态：历史记录。适用范围：2026-10-23 已实施的深化设计快照；自动开启、下一轮模式等旧默认值已被当前规范替代，不能据此改回旧行为，验收用例须按当前规范重新核对。
> 当前规范：[交易关卡](training-gate.md)。

本文记录交易关卡深化设计与验收边界，已于 2026-10-23 实现。基础规则见 [交易关卡](training-gate.md)；界面实现遵循 [UI 规范](../ui/ui-guidelines.md)。

## 目标与已确认决定

- 训练会话可以关闭连亏自动开启，或配置连续亏损触发笔数；现有会话默认保持“开启、2 笔”。
- 每轮关卡开始前选择“策略清单”或“交易计划”；本轮运行中模式固定，下一轮可改。自动开启使用预先保存的下一轮模式；默认仍为策略清单。
- 交易计划模式不要求选择已有 Setup，也不勾策略检查清单。下单前只强制选择六类市场背景之一，并填写一段非空的交易计划。
- 交易计划在对应交易日志生成时直接写入可编辑的复盘正文，不另设必须操作的“从快照导入”步骤。
- 背景判断提示图使用代码生成的 [SVG](market-context-decision-tree.svg)。保留附图 2 的判断分支、分支标签及末端交易提示内容，只调整视觉表现。

## 范围与术语

仅适用于 K 线回放的**模拟训练会话**；实盘重演不使用交易关卡。这里的“入场”沿用现有口径：开仓、加仓以及反向单实际打开的新仓；纯减仓、平仓、保护单不需要关卡确认，也不计关卡进度。挂单提交或撤销不计进度，实际入场成交才计一次。训练关卡已开始后仍须完成目标成交数，不能中途关闭。

“连续亏损”沿用现有结算口径：同一入场批次完全平完后汇总其分批平仓的净盈亏（含分摊手续费，滑点体现于成交价）；净亏算 1 次，盈利或保本清零。不得改用单根 K 线浮亏、单次平仓或完整持仓周期作为触发计数。

## 关卡配置与状态

| 配置 | 初始值 | 生效规则 |
| --- | --- | --- |
| 持续入场成交笔数 | 10 | 保持现有正整数限制；每轮启动时锁定为目标数。 |
| 连亏自动开启 | 开启 | 关闭后不再因新结算亏损启动关卡；仍可手动开启。 |
| 连亏触发笔数 | 2 | 正整数；仅自动开启时参与判断；输入范围与持久化校验一致。 |
| 下一轮模式 | 策略清单 | 手动或自动开启时复制为本轮模式；可在关卡未运行时调整。 |

- 未运行时可保存配置或“保存并开启”。运行中显示开启来源、模式和进度，配置只读；关闭弹窗不关闭关卡。
- 关闭自动开启、重新开启自动开启或修改阈值时，将**触发用**连亏计数归零；此后只看新结算的交易，避免以前的测试单追溯触发。保存未改动的配置不应清零。账户原有盈亏统计不受影响。
- 手动开启不受自动开关限制，并清零触发用连亏计数。关卡运行中不重复触发或延长。完成后清零触发计数，下一轮继续使用已保存的自动设置和模式。
- 重置训练会话时，沿用现有“保留关卡配置及开启状态、进度从零开始”的规则；新增的自动开关、阈值和本轮模式一并遵守。新训练会话从上述初始值开始，旧会话缺少新字段时按上述初始值读取，不追溯既往亏损。
- 同一源 K 线内发生第二笔亏损结算和反向入场时，先按既有撮合/关卡顺序结算并开启；未经**本轮模式**确认的新仓部分不得绕过检查。

## 两种模式的下单流程

两种模式都沿用现有“先确定订单参数，再做最后一步确认”的入口；检查窗口可对照图表，取消时保留本笔订单草稿，下单成功后清空。改变订单价格、数量或风险参数沿用现有确认快照；撤销后新建入场订单重新确认。

### 策略清单模式

保持现有流程：选启用且有检查项的策略，逐项确认，全部通过才能提交。策略版本、检查项和确认时间随订单、成交批次和日志保存；服务端按当前策略版本核验。此次需求不修改清单本身的编辑规则。

### 交易计划模式

确认窗口只设两个必填输入：

1. **市场背景**：每步只给两个选项，依次判断“趋势 / 交易区间”；趋势继续判断“突破 / 通道”，然后判断“强 / 弱”或“窄 / 宽”；交易区间继续判断“窄 TTR / 宽”。允许返回上一步修改判断，并保留当前订单草稿的未完成路径。最终值只允许：强势突破、弱势突破、窄通道、宽通道、窄交易区间、宽交易区间。必须由用户判断，系统不按 K 线自动推断，也不默认选中。趋势分支用柔和蓝色、区间分支用柔和绿色，绿色在此仅表示背景类别；选中状态还须有勾选和路径文字。提示图悬浮或聚焦时显示，鼠标离开图标及图片区域或失焦后关闭；点击不固定图片。
2. **交易计划**：一个自由文本框，去空白后非空才可提交。示例提示而非强制拆字段：“价格在〔位置〕出现〔动作〕，我预计〔走势〕；若〔失效信号〕则〔处理〕。”允许只写用户当下最关键的判断，不要求逐项填位置、动能、P1/P2/P3 或交易类型。

分类旁的提示图标在鼠标悬浮、键盘聚焦时显示 [判断图](market-context-decision-tree.svg)；触屏可点击打开，放大查看时不遮住当前已填写内容。提示图的文字与附图 2 一致：区间窄→“等待突破”，区间宽→“在顶部1/3或底部1/3等待突破失败”；突破强→“市价入场”，突破弱→“等待回调”；通道窄→“只交易窄通道的方向”，通道宽→“和宽区间一样的交易方式”。这些是**参考提示**，不自动变成订单类型或硬性下单规则。

背景只针对本笔做单依据的显示时间级别判断；确认时记录当时的显示周期与源 K 线序号，以便以后解释背景。更高时间级别关键区域可写在同一段计划里，不增加必填项。切换显示周期不得改变源序号、挂单生效序号、撮合路径或 OCO 行为。

交易计划模式不写入 `setupOptionId`；日志中仍可事后按现有操作人工标注 Setup，但不能把此标注伪装成入场前选择。两种模式均须在订单提交时由服务端验证本轮模式、必填数据与会话版本，前端按钮禁用不能代替服务端校验。编辑计划或背景时只影响本笔尚未提交的草稿；已提交挂单保留确认时原内容。

## 背景分类图的内容边界

分类树严格按附件 2：

```text
趋势 or 区间
├─ 区间 → 窄 or 宽
│  ├─ 窄 → 等待突破
│  └─ 宽 → 在顶部1/3或底部1/3等待突破失败
└─ 趋势 → 突破 or 通道
   ├─ 突破 → 强 or 弱
   │  ├─ 强 → 市价入场
   │  └─ 弱 → 等待回调
   └─ 通道 → 窄 or 宽
      ├─ 窄 → 只交易窄通道的方向
      └─ 宽 → 和宽区间一样的交易方式
```

UI 用语可在选项中展示完整六分类名称，图中的分支和末端文案不改写。图使用项目浅色、蓝色强调与 Slate 中性色；连接线及标签均可辨认，不仅靠颜色表达层级。小屏先保证文本可读，允许图在浮层内部缩放或滚动，不让整个页面横向溢出。

## 复盘正文模板与写入时机

交易计划是**下单前**记录，第 3 项“实际持仓过程”只能在入场后填写。原六部分保留为复盘结构，但下单前只填“背景 + 一段计划”。不把事后观察回填成“当时已知”。

交易日志首次生成时，按对应入场订单的背景与计划，在其 `review` 正文写入以下模板。日志现在按 FIFO 匹配的入场批次及平仓生成；一次入场分批平仓可对应多条日志，每条只写入一次相同的下单前内容，事后执行过程分别填写。

```text
1、入场前已知事实
背景（下单时记录，做单级别：{显示周期}）：{六分类}
位置与动能（遮住未来后需要时补充）：

2、交易假设与管理预案
计划来源：当时已记录
下单前交易计划：{原填写内容}
管理预案（需要时补充）：

3、实际持仓过程与执行对照

4、与同类盈利单比较（仅亏损单）

5、亏损单归类（仅亏损单）

6、下一步（只写一项）
```

- 第 1 节的“位置与动能”及第 2 节的“管理预案”是**事后可补**提示，不作为下单前必填；补写时用户应区分当时记录与遮住未来后的重建。第 3 节按时间顺序记录实际发生的 2–4 个关键节点，未经历的阶段可写“未发生”。第 4、5 节仅在亏损单填写；第 5 节沿用“规则内亏损／条件或规则未满足／止损或目标位设计问题／管理执行问题／待判定”。第 6 节只选一项：保留规则、纠正执行或提出待验证假设，并给出具体行动。
- 正文由系统首次写入后仍按现有复盘编辑方式修改，不另加导入按钮。若该日志已存在正文，重建、重试、同步或再次读取都保留用户编辑，不覆盖、不重复追加。旧日志保持原样，只有新产生且来自交易计划模式的日志自动写入。
- 取消或未成交的挂单不产生交易日志，也不创建复盘正文。下单时的计划仍随已提交订单保存，用于后续成交与日志生成；不能仅存在浏览器草稿里。
- 复盘正文现有上限为 2000 个 Unicode 字符。交易计划最多输入 800 个 Unicode 字符；模板连同最长计划仍低于正文上限，为事后填写留出空间，界面显示已用字数。

## 数据与兼容设计

- 在会话 `trainingGate` JSON 状态中增加自动开启开关、触发阈值、下一轮模式和本轮模式；旧 JSON 缺字段时填默认值。运行中以本轮模式为准，修改配置不能回写本轮历史。
- 扩展现有订单、持仓批次、日志的 `discipline` JSON 为带 `mode` 的区分联合：旧记录无 `mode` 按策略清单读取；新策略清单记录包含策略快照；新交易计划记录包含背景枚举、计划原文、显示周期、确认时间及源序号。不得丢掉旧清单快照，也不把交易计划伪装成已完成清单。
- 自动或手动开启时，对未获**本轮模式**有效确认的待成交入场挂单按现有撤单规则处理；保留纯平仓单和保护单。已获另一模式确认的待成交入场单也应撤销，避免切换模式后绕过本轮要求。
- 使用既有训练会话作用域、版本与 `X-Replay-Projection` 冲突校验；在服务端验证确认输入和同步重放，幂等重试不能重复成交、重复计数或重复写复盘。行情推进与账户、订单、成交、日志、关卡进度的持久化仍保持原子性。
- 优先复用现有 JSON 字段，无数据库结构变更时无需迁移；若实现确需新增字段或表，按项目规则同步 Prisma 迁移与 `scripts/init-sqlite.mjs`，对实际库升级前依 [升级指南](../operations/upgrade.md) 核对并备份。

## 验收场景

1. 老训练会话显示自动开启、阈值 2、清单模式；未有新结算亏损时不会追溯触发。关闭自动开启后连续亏损不会启关，手动开启仍可用；修改阈值或重新开启后只计算新结算亏损。
2. 自动触发采用已保存的下一轮模式。运行中配置只读且本轮模式固定；完成后可切换下一轮模式。关卡成交数、亏损结算和重置行为保持既有口径。
3. 交易计划模式选择六分类并输入非空计划才可提交；不选 Setup、也不需清单。空白计划、非法分类、过长计划、旧页面版本或不匹配的模式均由服务端拒绝。
4. 分类提示图在悬浮、键盘与触屏可查看，内容与附图一致；375、1280、1440、1920px 下文字可读、浮层不超视口，页面不出现横向溢出。
5. 市价、限价、止损、加仓、反手的新仓、分批平仓和未成交撤单均按相应模式正确保存或免检。跨模式的旧入场挂单不会在新一轮关卡中免检成交。
6. 交易计划随订单进入持仓批次；每条对应日志首次生成时写入模板，Setup 初始为空。分批平仓、刷新、源周期推进、同步重放及幂等重试不会重复追加；已编辑的正文保持不变。
7. 策略清单模式及旧日志继续正常显示原有确认记录。实盘重演不出现关卡配置或强制下单检查。
