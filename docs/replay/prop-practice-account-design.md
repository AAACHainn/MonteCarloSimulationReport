# 期货自营练习账户：当前功能规格

更新日期：2026-10-30。本文说明当前生效的功能规则、交互和数据边界，供后续开发与验收使用；失败平仓及用户钱包扣费说明已按现有实现核对，已知实现缺口见第 10 节。本次仅修正文档，不代表重新完成了全部测试或浏览器验收。

相关文档：[开发日志与决策记录](prop-practice-account-development-log.md)、[分阶段实施与验证记录](prop-practice-account-implementation.md)、[账户模式调研](../research/prop-firm-account-models-2026-10-23.md)、[现有会话机制](replay-sessions-implementation.md)、[桌面 UI 规范](../ui/ui-guidelines.md)。

本文在现有模拟交易之上定义账户考核、出金和结果记录，不追求完整复刻公司的成交或盘中风控。开发日志保留需求演变及撤回方案，实施记录保留当时的验证证据；其中的历史规则、授权范围和测试结果不能覆盖本文的当前规则。后续用户明确确认的新需求优先，确认后同步本文；发现本文与实现不一致时须核对最终需求，不按旧方案回退已确认的功能。

## 1. 不可突破的复用边界

**自营练习仅增加账户类别、账户规则及轮次管理。现有交易、下单、成交、关卡业务算法全部复用。**

| 必须保持的部分 | 明确边界 |
| --- | --- |
| 撮合与订单处理 | 不改变价格路径、订单优先级、生效序号、成交价格、部分减仓、反手、止盈止损、OCO 或当前价格平仓 |
| 数量和风险金额 | 不新增整数手数、合约张数、最大仓位、mini / micro 换算，不改变原数量与风险金额计算 |
| 盈亏、费用和滑点 | 继续使用当前计算及已有配置，不引入合约点值、每手佣金、tick 滑点或新计价模式 |
| 交易关卡 | 完整复用现有关卡触发、策略检查、清单、计划、连亏和完成计数；账户规则不能替代、绕过或重置关卡 |
| 数据和回放 | 继续使用源 K 线推进与现有揭示规则；不补造 K 线、不增加源 K 内风险触发点、不截断已执行的源 K |
| 默认模拟账户 | 保留现有创建、交易、训练 / 实盘重演、统计、归档等行为 |

实现上允许在会话编排层增加账户可用性检查、消费既有处理结果、写入自营账本和复用归档；不能以接入账户规则为由修改原业务算法。

**最大回撤失败会触发自动全平和撤单。** 账户层在完整源 K 或原用户操作结果之后，复用现有当前价格平仓流程，以最后已揭示源 K 收盘价为基准处理剩余持仓并撤销待成交挂单；不新增源 K 内触发点，不把成交价改成风险线。晋级、申请出金及主动归档不替用户平仓或撤单，仍须满足各自前置条件。原有 OCO、保护单和关卡逻辑继续复用。

## 2. 已确认的产品流程

- 先创建会话，再在会话内创建账户时二选一：默认模拟账户，或自营练习账户；账户创建后不能切换或并存。会话用途仍在创建会话时固定。
- 用户先保存自营规则模板，在会话内创建账户时选择模板，复制为固定规则快照。未被任何账户使用的模板可以直接修改或删除；存在账户引用时仅允许复制为新模板，不覆盖原规则。
- 自营练习固定为现有训练模式，禁止回退及删除单个交易周期；原“重新开始”仍归档旧会话。“重新考核”只为已经失败的账户建立新轮次，不归档整个会话，不回退行情。
- 同一会话可依次包含多个账户轮次，每轮最多一个考核阶段和一个出金阶段；同一时刻只有一轮可交易。
- 考核利润保留在历史中，不计入出金阶段的初始资金；出金按模板单独配置的初始资金开始。
- 手动申请出金，系统计算上限，用户可填写金额；确认后立即模拟扣款并记录分成后实得。
- 出金成功后当日暂停账户交易，下一交易日恢复；可选开启合格盈利日要求，每次成功出金后重新累计，不另设周期利润或一致性门槛。
- 基本信息记录“账号成本”：购买金额及可选激活费。归属用户的训练会话首次创建或重新考核时从用户钱包扣购买费；手动确认转为出金账户时扣非零激活费。未归属会话不接入用户钱包；具体扣款边界及自动晋级缺口见第 3.1、10 节。
- 钱包记录练习资金的购买、激活和出金流水，不涉及真实转账或券商连接。钱包扣费不改写自营阶段余额、交易盈亏、回撤或交易者累计实得。

账户类别、业务阶段、会话状态、结束原因分别记录，不把“已归档”当作业务结果。

| 情形 | 处理与主标识 |
| --- | --- |
| 目标暂未达到 | 继续考核，不直接归档 |
| 考核失败 | 冻结本轮并暂停，显示“考核未通过”，会话保留，可重新考核 |
| 出金阶段失败，未成功出金 | 冻结本轮并暂停，显示“出金失败”，可重新考核 |
| 出金阶段失败，已有成功出金 | 冻结本轮并暂停，主标识为“成功出金 $X”，详情保留失败原因，可重新考核 |
| 用户提前主动归档 | 显示“考核中止 / 出金中止”，已有出金同时展示，不伪称规则失败 |
| 行情用完或统计边界无法判断 | 暂停并说明，不推断失败，不补造统计或成交 |

X 为本轮分成后累计实得。考核和出金阶段失败时，按失败观察点已揭示源 K 收盘价为基准市价全平，沿用原滑点、手续费、FIFO、交易统计和关卡结算，撤销本轮全部待成交挂单，再冻结并暂停。平仓成交、交易日志、图表标注和失败状态在同一事务内保存；失败证据保留平仓前触发时的权益与底线，最终余额和阶段指标包含平仓成本。主动归档仍是独立操作，不自动平仓。

### 2.1 失败后的重新考核

- 仅失败轮次提供“重新考核”；考核和出金失败均以原快照的考核初始资金开始新轮，不直接恢复出金资格。行情用完时先提示无下一根，追加后再重开。
- 保留当前源序号，下一次推进执行下一根；不重放失败源 K，不再次执行旧轮已经完成的失败平仓，新轮空仓无挂单。
- 每轮独立保留引擎账户、订单、成交、权益、规则状态、账本、提款和结束证据。旧轮不可继续交易；失败平仓进入正常日志及胜负统计，主动归档时仍未平仓的交易单独展示且不加入胜负统计。
- 规则、源日历、币种、费用滑点及账号成本继承原快照。归属用户的训练会话每次重新考核按新轮次再次扣购买费，先检查钱包余额能覆盖购买费与激活费合计；新轮的手动晋级再扣该轮激活费。余额不足时整次操作回滚，同一请求重试不重复扣费；未归属会话不扣钱包。风险金额偏好、绘图和会话关卡的开启状态、连亏及完成计数原样保留。
- 新轮交易盈亏、费用、峰值与回撤、考核日数、一致性、出金合格日和提款计数独立初始化；旧轮累计实得保留，会话汇总实得不进入新轮余额或可提利润。跨轮不拼接净值计算最大回撤。
- 操作原子切换当前轮，带版本、执行结果身份和请求编号；重试只返回原回执。并发最多成功创建一轮，旧订单/推进请求不能写入新轮。
- 历史页提供全部轮次及单轮查看，日志标注轮次，复盘与交易链接保留；删除整个会话才级联删除其全部轮次。迁移把原账户完整标为第 1 轮，不自动重新打开已归档会话。

## 3. 模板配置与继承项

一个模板包含两个阶段及一组出金规则。公司名仅作备注，不参与逻辑。

按业务项统计，共 22 项：基本信息 4 项、考核阶段 7 项、出金阶段 11 项。“账号成本”为 1 组，包含购买金额和激活费用 2 个金额字段；可选开关和对应金额仍按同一业务项计数。

### 3.1 基本信息与继承项

| 项目 | 方案 |
| --- | --- |
| 名称、说明、启用状态 | 支持新建、复制；未被账户使用时可直接修改、设置启用状态或删除，已被使用时只能复制 |
| 账号成本 | 购买账号金额、考核通过后的激活费用；两项分别保存，单位继承账户币种，允许非负金额。激活费用明确为选填，无需激活费的账户可留空或填 0；留空表示未填报，0 表示明确无需支付 |
| 初始资金 | 两阶段分别配置，均大于 0，沿用现有正数及范围约束；不扩展 0 起点模式 |
| 币种 | 继承创建时现有模拟账户配置；两阶段与全部规则金额使用相同币种 |
| 费用 / 滑点 / 下单参数 | 继续使用原配置入口与语义，两个阶段沿用，不在模板新增第二套费用或数量规则 |
| 交易日定义 | 继承并快照现有数据集权威时区及源交易时段，复用现有日期 / 时段归属能力 |
| 图表设置 | 显示周期、图表时区、ETH / RTH 切换不改变账户交易日归属 |

不建立独立的模板交易日历、交易禁窗或收盘强平配置。数据集现有信息不足以解释交易日时，在创建时提示补全已有设置；不能擅自猜测交易日或引入新交易时段限制。

账号成本随模板规则保存，创建账户时复制到固定规则快照，各轮使用该快照；后续模板变化不能改动已有账户的费用。扣款记录在用户钱包账本，购买与激活按会话和轮次去重；重新考核产生新轮次，须再次扣购买费。不从自营阶段余额或累计实得中扣成本，不用于交易盈亏、回撤、关卡或可提额公式。

激活费用未填写时，不阻止模板保存、会话创建、考核通过或进入出金阶段；不得自动补默认费用或要求补填。

#### 钱包扣费与交易账本的边界

以下钱包操作仅适用于有用户归属的训练会话，未归属会话及实盘重演不参与：

| 操作 | 当前实现 |
| --- | --- |
| 首次创建自营账户、每次重新考核 | 检查可用余额能覆盖购买费与激活费合计，但当次只扣购买费。此检查不冻结或预留激活费，之后余额仍可能不足。 |
| 手动确认转为出金账户 | 激活费非零时重新检查余额并扣款，与阶段切换在同一事务完成；不足则整次切换回滚。未填写或 0 不扣费。 |
| 日终自动晋级 | 当前自动路径没有调用钱包激活费扣款，属于第 10 节列明的实现缺口，不能视为已确认的免费规则。 |
| 成功申请出金 | 自营账本扣申请额，用户钱包只增加交易者分成后实得；购买费与激活费不退。 |

实现入口为 [用户钱包服务](../../lib/user-wallet/service.ts)、[首次账户初始化](../../lib/replay-sessions/service.ts)、[重新考核](../../lib/prop-practice/rounds.ts)和[手动晋级与出金](../../lib/prop-practice/service.ts)。钱包使用整数分及唯一来源键维护余额和流水，与原交易账本分开；不因文档修订补扣历史费用或改写历史交易。

### 3.2 两阶段分别配置的风险规则

| 配置项 | 可选值与含义 |
| --- | --- |
| 最大回撤额度 D | 固定账户币种金额，必须大于 0 |
| 回撤模式 | 仅静态 / 日终余额追踪 |
| 追踪底线封顶 | 不封顶，或“本阶段初始资金 + 偏移”；静态模式隐藏 |

最大回撤固定为观察权益小于或等于底线即失败。两个阶段均不配置每日亏损失败线，也不提供每日损失暂停或其它日损规则；不得在后台保留隐藏额度。

两种模式只决定最大回撤底线如何产生，不改变原成交。风险检查仍读取每根源 K 或原用户操作完成后的快照；日终追踪仅在日终抬高底线，不能把“只在日终更新底线”误解为“只在日终检查失败”。**同根源 K 内权益触线后收盘恢复，现有快照未反映该触线时，本方案不会据此失败。**

“追踪底线封顶”是指日终追踪的最低权益线涨到指定值后不再上涨，不是限制账户余额或利润。例如初始资金 50,000、回撤额度 2,000、封顶底线 50,100：

| 历史最高日终余额 | 生效底线 |
| --- | --- |
| 50,000 | 48,000 |
| 51,000 | 49,000 |
| 52,100 | 50,100，达到封顶 |
| 55,000 | 仍为 50,100 |

封顶后盈利可以继续增长，余额下跌也不会使底线下降；不封顶则继续随新的日终余额高水位抬高。静态回撤的底线从一开始就固定，不使用追踪封顶。

### 3.3 考核通过条件

全部已启用条件满足，且当前空仓、无待成交订单时通过。

| 配置项 | 规则 |
| --- | --- |
| 净利润目标 | 阶段累计已实现净利润达到目标；浮盈不用于通过 |
| 最少交易日 | 可关闭；有实际成交的不同账户交易日计一次，挂单不计 |
| 一致性 | 可关闭；最大盈利日 / 阶段累计净利润 ≤ 比例 |

考核不配置“最少合格盈利日数”或“合格日净利润门槛”，不保留对应开关、计数器或隐藏通过条件。四家期货产品的既有调研未找到考核采用“至少 N 天、每天净利 ≥ W”的明确要求；报告中的此类要求属于部分 funded / PA / XFA 产品的出金条件，不能移入考核。普通最少交易日不要求当天盈利；一致性可能使利润必须分散到多日，但不另建固定盈利日数或单日盈利门槛。来源与复核时间见[开发日志第 13 节](prop-practice-account-development-log.md#13-原设计修订记录归档)。

支持两种晋级入口：交易日结算后的自动晋级，以及“模拟账户”内的“转为出金账户”按钮，盘中满足全部考核条件即可手动切换。手动预览将当天截至当前的原已实现净利润（含费用）、实际成交日和一致性纳入判断，浮盈不计；不加入考核最长期限。

有持仓或挂单时只显示尚未满足，用户通过现有入口自行处理，账户层不自动平仓或撤单。自动晋级继续使用已结算统计；手动晋级使用包含当前日的完整已实现结果，必须同时满足当前空仓、无挂单、账户未结束、权益高于底线，且状态为可交易或行情用完（`NONE` / `DATA_END`）。行情用完本身不否定已经满足的考核条件，切换后仍需追加行情才能继续交易。不能拿旧日终成绩跳过本日的新亏损或费用；风险失败优先于切换。

考核阶段净利润小于等于 0 时，不计算一致性比例；已启用的一致性条件判为未满足，不能当成跳过校验。超出一致性时继续考核，不判失败。当前采用无业务缓冲的比例模型，等于配置比例时满足该条件：

~~~text
所需净利润 = max(原净利润目标, 最大单日净利润 / 一致性比例)
~~~

自动晋级使用已结算日，手动晋级包含当前日截至当前的已实现净利润；统计均扣除原交易费用，不计浮盈。按原结果精度判断，界面金额显示的四舍五入不提供额外容差。最大盈利日在同一天继续增长时，所需净利润也会增长。

例如目标为 6,000、一致性为 50%，假设以下金额均为扣费后的精确净利润，且满足其它通过条件：

| 每日净利润 | 累计净利润 | 最大单日净利润 | 所需净利润 | 一致性是否满足 |
| --- | --- | --- | --- | --- |
| 第一天 3,000；第二天 3,001 | 6,001 | 3,001 | 6,002 | 否 |
| 第一天 3,000；第二天继续赚 1，变为 3,002 | 6,002 | 3,002 | 6,004 | 否 |
| 第一天 3,000；第二天停在 3,001；第三天赚 1 | 6,002 | 3,001 | 6,002 | 是 |

机构特有的一致性缓冲未纳入当前规则；是否引入及其算法尚未确认。调研发现不自动转化为模板选项，详见第 10 节及[开发日志第 14 节](prop-practice-account-development-log.md#14-一致性边界与机构缓冲复核)。

考核通过后初始化出金阶段资金和风险状态。日终自动晋级仍暂停播放，出金阶段从下一个实际交易日开始；若借下一日首根确认上一日结束，该首根尚未执行，恢复后处理原首根，不再额外延后一天。手动切换先暂停播放并等待在途推进及交易写入完成，服务端重新校验后原子记录阶段、事件、命令与检查点；确认后当天即可继续交易，行情从下一根未处理的源 K 开始，不跳过或重放当前源 K。**原关卡、连亏、完成计数及风险金额偏好原样保留**。

盘中切换时，考核当日记录标为“阶段结束”，不假装完成交易日日终，不提前抬高 EOD 高水位或底线。新出金阶段以当前 rawNet 为利润锚点、以模板出金初始资金开始；同一账户交易日可分别有考核和出金记录，按锚点切分盈亏与费用，不重复计入。当天合格盈利日只读取切换后出金阶段有实际成交的已结算日记录，考核利润和成交不带入。请求重试或并发不得重复创建出金阶段，也不能重置后续已经累计的出金利润。

### 3.4 出金资格与额度

机构与账户产品的出金条件并不统一。合格盈利日要求仅在出金阶段提供可选开关；每次成功出金后重新累计。每周期最少交易日、周期最低净利润和周期一致性仍不提供，也不在后端隐式保留。机构与账户类别对照见[调研文档第 9 节](../research/prop-firm-account-models-2026-10-23.md#9-四项出金资格条件复核)。

本节是按用户要求收敛后的简化练习规则，不代表能够完整复刻存在上述要求的公司产品。考核通过条件仅保留第 3.3 节的净利润目标、可选最少交易日和可选一致性；合格盈利日仅在出金阶段配置，默认关闭，按所练习产品自行配置。

| 配置项 | 规则 |
| --- | --- |
| 合格盈利日 | 可关闭；开启时配置最少日数 N 和单日净利润门槛 W，仅出金阶段统计，每次成功出金后重新累计 |
| 最低申请金额 | 正数 |
| 可提比例 | 尚未提取累计交易净利润的 0%–100%，不含 0 |
| 单次申请上限 | 可关闭或正数金额 |
| 保留利润缓冲 | 可关闭；开启后提款后余额至少为阶段初始资金 + 非负缓冲 |
| 交易者分成 | 0%–100%，不含 0 |
| 首次出金后永久底线 | 保持原规则，或至少提高至阶段初始资金 + 偏移 |

申请必须空仓、无待成交订单，账户不在阶段等待、出金日暂停或归档状态；账户规则不替用户清仓。

合格盈利日仅统计已结算、有实际成交且当日原交易净利润（已实现盈亏减费用）≥ W 的不同账户交易日，每日最多计一次。考核历史、纯浮盈、无成交日、未结算日均不计入。日切与同源 K 当前价格平仓沿用原日终结算流程，先更新完整费用和净利润，再计算资格；打开弹窗或查询预览不提前结算。

申请时记录当前交易日，此后当日不能再交易。成功出金后只推进合格日统计起点，下一出金统计周期仅统计出金日之后的账户交易日，出金当日不能再次计入；保留完整历史日账本，不改写原交易净利润。失败申请、刷新、暂停恢复和请求重试不重置计数。

出金确认后更新累计申请额、累计实得、提款次数和恢复交易日期，每天最多一次出金；提款不重置出金阶段净利润锚点、回撤高水位、风险底线或交易关卡。

关闭合格盈利日规则时，下一交易日即使尚未产生新盈利，只要仍有尚未提取的累计利润且满足金额与风险约束，也可继续申请。开启时则必须先重新满足 N 个合格盈利日；不再叠加周期利润、普通最少交易日或一致性要求。表单展示当前已结算合格日数、所需日数、日净利润门槛及每次出金重计说明。

不配置最多提款次数或不同次数对应不同上限；已提款后继续练习，直到规则失败或用户主动结束。

### 3.5 配置合理性校验

- 初始资金、目标、回撤、提款金额、比例和计数必须有限且有资源上限，金额用统一账户币种；自营金额配置及申请金额最多 2 位小数，规则计算保留原交易结果精度；关闭规则用显式开关。
- 两阶段初始资金均大于 0；不修改现有账户正数校验，也不从账户类别改变原风险金额和下单数量计算。
- 购买金额和激活费用分别允许留空或非负有限金额，并限制输入范围与金额精度；激活费用必须按选填校验，缺省不报错。0 与未填写分别保存，钱包扣款均按无需收费处理。费用参与第 3.1 节的钱包校验与扣款，不加入自营交易余额、权益、盈亏或可提额公式。
- 仅考核阶段：最少交易日启用时须为正整数；仅有实际成交的不同账户交易日计数，不要求当天盈利，不因挂单、提款或阶段资金变化增加天数。
- 仅出金阶段：合格盈利日规则启用时，N 为 1–10000 的整数，W 为正数金额且最多 2 位小数；关闭时不校验日数资格。成功出金后重计，不影响累计利润和风险状态。
- 仅考核阶段：一致性比例在 (0, 100%]；关闭时不执行比值判断。展示比例隐含的最低盈利日数，避免用户误认为 40% 可以一天通过。
- 追踪封顶不得低于初始底线。首次出金永久底线可以高于追踪封顶，两者不是同一项，永久底线不受追踪封顶下调。
- 最低申请不得大于已启用的单次上限。预览解释比例、缓冲和底线限制，实际可提不足最低额时清楚显示原因。
- 实得按现有金额精度结算后必须为正。新账本的精度不能反向舍入或改写原有成交、费用与关卡输入。
- 日切、显示时区、模板编辑、暂停和重启应用不能改变已有快照与计数。

## 4. 独立自营账本，不改变交易盈亏

### 4.1 资金公式

每轮底层引擎维护该轮原账户和累计成交结果，自营层记录该轮各阶段起点锚点；旧轮结果独立保留，不加入新轮公式：

~~~text
rawNet = 本轮原账户累计已实现盈亏 - 本轮原账户累计费用
P = 当前 rawNet - 本阶段起点 rawNet
B = 本阶段初始资金 B0 + P - 本阶段累计申请金额 G
E = B + 原快照未实现盈亏
本日净利润 = 日末 rawNet - 日初 rawNet
~~~

本日净利润服务于日终账本、考核一致性与出金合格盈利日统计；出金阶段不额外设置周期净利润目标或周期利润锚点，合格日重计只移动日统计起点。

B / E 分别是自营练习余额 / 权益。**它们不回写底层 initialCapital、realizedPnl、费用或峰值，不改写既有 risk-sizing 或关卡算法。** 会话级风险偏好只为新订单草稿生成默认风险金额；默认模拟使用原账户余额，自营练习使用本轮当前阶段余额，之后仍按原下单和数量计算流程处理。

现有滑点已经体现在成交价和原盈亏内，不能再扣一次。资金切换、提款和分成不是交易盈利或亏损，不能影响原胜率、连亏、关卡或交易日志结果。

账号购买金额及激活费用按第 3.1 节处理用户钱包扣款，不计入 rawNet、P、B、E、R、累计实得或原交易费用。钱包可用余额与本节的自营阶段余额是不同账本，不能因发生钱包扣费而重新计算交易结果。

创建时，底层账户初始资金使用模板考核初始资金，通过原有创建校验；费用、滑点等保持原入口。晋级时只更新自营阶段的 B0 和 rawNet 锚点，不重新创建底层账户、不清零累计成交历史。

底层交易统计继续原口径。自营账户卡片统一使用当前阶段：已实现盈亏为本阶段费前已实现盈亏，手续费只累计本阶段，“本阶段交易净利润”为二者之差；未实现盈亏、持仓和均价使用当前原快照。出金阶段开始时已实现盈亏、费用和最大回撤均从零开始，考核历史保留在原账本及阶段历史中，不清零底层累计值。默认模拟账户卡片不改变统计口径。

卡片最大回撤按本阶段交易权益计算：`统计权益 = 本阶段初始资金 + 本阶段交易净利润 + 未实现盈亏`；逐源 K 完成及原用户操作完成后更新统计峰值，最大回撤为历史最大的 `(统计峰值 - 统计权益) / 统计峰值`。包括手续费和浮盈亏，不把源 K 内各笔撮合当作额外权益观察点；同源 K 当前价格平仓仍消费完整原结果。提款不作为交易亏损，不降低统计权益或重置该最大回撤；实际余额、剩余回撤额度及失败风险继续按原独立账本扣除提款，两种口径不能混作一条风控线。统计峰值与风险规则的日终高水位独立，不能用它盘中上调亏损底线。

阶段显示指标及累计值锚点存入已有阶段 JSON，不增加数据库表或列。旧记录缺少指标时，按阶段源序号范围分块读取原成交与源 K 收盘数据只读还原；不能用稀疏权益采样冒充完整最大回撤，不重新撮合或改写原成交。读取不回写历史，之后正常账户操作在原事务中维护新指标。

不再并列显示重复的原账户摘要。需要展示底层余额的明细明确称为“原模拟账本余额”。导出区分原交易结果与自营资金流水，不重算原成交盈亏；全部轮次汇总不拼接跨轮净值计算最大回撤。

### 4.2 回撤公式与观察顺序

~~~text
初始化 H = B0，T = B0 - D，永久底线尚未生效
初始底线 = B0 - D
静态追踪项 T = B0 - D
日终追踪项 T = min(封顶值, max(既有 T, H - D))
未设封顶时，忽略 min 的封顶项
生效底线 F = max(T, 已生效永久底线)
失败：观察权益 E ≤ F
~~~

H 使用自营账本自己的高水位，不复用原模拟账户 peakEquity：

- 日终追踪：在账户交易日结算后，用该日最终自营余额 B 更新 H。
- 静态：不随盈利更新底线，但可应用首次提款后的永久底线。

每次先按旧底线检查失败，再按该观察点的规则更新 H / T，最后按新底线检查一次；风险失败优先于晋级和出金。首次提款永久底线取 max(既有永久底线, 配置值)，不会降低已经生效的底线。

两阶段只按最大回撤底线检查风险，不计算单独的每日损失额度。日终余额追踪的 H 不因源 K 完成、用户平仓或提款而盘中上调，只在第 5 节约定的日终结算时更新；上述操作完成后的权益仍须对当前已生效的底线检查失败。

### 4.3 可提上限与流水

~~~text
R = max(0, 出金阶段 P - 出金阶段累计申请 G)
F_after = 本次出金后将生效的底线

可提上限 = max(0, min(
  R × 可提比例,
  单次上限（若开启）,
  B - (B0 + 利润缓冲)（若开启）,
  B - F_after - 安全余量
))
~~~

当前自营金额统一使用 2 位小数，安全余量为 0.01，上限向下取整到分；不得因二进制浮点表示使合法的分金额额外少一分。风险判断使用原结果精度，不把实际跌线的小数四舍五入成未跌线。提款后必须严格高于 F_after。

确认时服务端在同一事务内重新验证资格、金额、会话版本和空仓 / 无挂单条件，再写流水：

~~~text
申请 A：最低额 ≤ A ≤ 当前可提上限
账户扣款 = A
交易者实得 = 按金额精度结算(A × 分成比例)
规则分成 = A - 实得
~~~

申请 1,000、分成 90% 时扣款 1,000、实得 900；不只扣 900，也不额外再扣一次分成。事务失败时全部不生效；相同请求重试返回原记录，不重复扣款。

提款前若当前源 K 同时是实际日终边界，先完成一次 EOD 风险更新，再计算 F_after；提款后不会拿扣减余额抬升或降低已有高水位。下个交易日按既定日期恢复交易，不重置最大回撤底线，也不建立每日损失额度。

## 5. 撮合与失败平仓

观察输入只来自**现有完整撮合结果**或**现有用户操作完成结果**，不访问或扩充引擎内部路径。

1. 先检查待处理源 K 是否跨入新交易日；跨日时先用上一日最后完成快照结算并检查风险 / 晋级。若本轮失败或晋级，则在执行新日首根之前停止，保留该首根待恢复处理。
2. 账户允许继续后，按原流程执行一整根源 K，保留其全部订单变更、成交、持仓、费用和关卡结果。
3. 账户规则层读取完成快照，处理账户交易日归属、自营权益和资格。
4. 若失败，撤销全部待成交挂单，在当前已处理源 K 收盘价上通过原引擎执行市价全平（含滑点与手续费），在同一原子提交中保存完整成交、日志、权益、关卡及失败证据，再冻结本轮并暂停。若原保护单已平仓，不重复平仓；跨日结算触发失败仍使用上一日最后已处理源 K，不执行新日首根。会话不自动归档。
5. 若通过考核，要求现有快照已经空仓无挂单，记录阶段切换；不自动生成平仓或撤单。
6. 如果既有用户操作改变账户资金，例如当前价格平仓，操作全部按原流程完成后再观察账户规则。
7. 不改变账户资金的已有操作只复核资格 / 可用性，不生成虚假的交易日、盈亏或重复风险样本。

同一根源 K 可能先亏损、后反弹，也可能有多笔成交；不能在事后删掉本根部分成交、倒退到假设触线时刻，或把成交价改成风险线价格。

批量处理可在源 K 边界提前停止，响应必须返回实际最后完成序号。规则在稀疏权益采样之前消费每根既有结果，不能只从落库的少量权益点恢复风险。

自营类别不使用跨日空仓汇总快跳，走逐源观察路径；默认模拟继续使用原 flat-advance 优化，不改其数学和成交规则。批量与逐根推进的账户结果必须相同。

### 日终与暂停细节

- 以现有数据集源时段确定账户交易日，固定使用该账户创建时的快照，不随图表 ETH / RTH 视图变化。
- 日界线通过已揭示源 K 的覆盖区间与现有时段信息判断。若能证明日末且已经空仓，该日不再有同源 K 的合法平仓成交，可结算；仍有持仓时先保留待结算日记录，不提交新的 EOD 高水位，等原入口平仓至空仓或进入下一实际交易日再最终结算。
- 在日末同一根源 K 上的原当前价格平仓仍然可用；其新增已实现盈亏和费用更新同一天的最后快照、净利润与资格，不新增一天、不计入下一日。此前按既有生效风险线已发生的失败不能撤销。
- 待结算日不能先用有仓余额抬高 EOD 底线并判定失败、再设想用户随后平仓降低底线；只使用最终日末快照提交该次 EOD 更新，避免账户层抢在原合法平仓操作之前改变结果。
- 跨日时先按上一日最后快照结算，再处理新日第一根；不得把新日首根的盈亏算进上一日，也不得在上一日失败后继续执行新日。
- 源 K 跨越无法准确划分的日界线时，只暂停并说明配置 / 数据问题，不改 K 线粒度、不补行情、不擅自归档失败。
- 有持仓过夜沿用原交易能力，不自动强平。日净利采用已实现结果差额，未实现浮盈不计入考核净利润或一致性的日利润统计。
- 阶段等待和出金日暂停均发生于空仓无挂单状态；阻止账户交易写入，但允许推进已有行情至下一交易日，不会冻结等待成交的保护单。出金当日的 `PAYOUT_DAY` 仅限制交易，不能反复发出停止播放信号，连续播放、显示周期推进与按日期批量推进均可继续；到下一实际源交易日自动恢复。恢复依据回放源行情时间，现实时间经过一天、切换显示时区或浏览未来图表都不改变账户状态。新发生的考核自动晋级、规则失败、日界异常和行情用完仍按原规则暂停。
- “确认继续”仅恢复播放；不改变已经生效的晋级 / 出金结果。关卡仍保持原状态。

## 6. 页面与交互

### 模板管理、会话与账户创建

“自营练习模板”管理页，支持保存、复制、修改和删除。模板未被任何账户引用时可以直接修改（包括启用状态）或删除；只要任一历史规则记录仍有账户引用，就禁止修改、停用或删除，仅可复制为独立模板。归档、考核失败和已有出金的会话都计入引用，只有关联会话全部彻底删除后才解锁。界面显示引用账户数量及禁用原因，删除使用统一确认弹窗，提交期间禁用重复操作。模板卡片及创建账户的选择器不展示版本号。表单仅包含第 3 节的账户规则，不出现张数、点值、最大持仓、新交易成本模型或关卡参数。

服务端在原 SQLite 写事务内重新检查模板修订号和全部规则记录的账户引用；保留现有外键 Restrict，不通过级联删除模板清理账户。修改未使用的模板只保存一份当前规则，不累积旧版本；内部修订号仅用于并发校验。替换规则记录标识，旧选择器提交返回冲突并要求刷新，不能默默使用用户未确认的新规则。已有多版本数据不批量迁移或自动清理：有引用时全部保留，无引用时仅在用户修改或确认删除该模板时处理。

考核阶段在“模拟账户”底部显示“转为出金账户”，未满足条件时禁用并说明所需条件；确认弹窗说明新的出金初始资金、考核利润保留及当天可继续交易。手动切换不会新建会话、底层账户或改变回放位置。

基本信息提供“账号成本”分组，分别填写购买金额和可选激活费，留空或 0 按无需收费处理。当前界面已提示归属用户的训练会话购买、重新考核和晋级扣费，以及费用不改变交易盈亏与回撤；该概括不能证明自动晋级已完成扣费接入，现有限制见第 10 节。

新建会话填写名称、用途和起始时间，日期时间选择器默认展开；进入会话后，通过工具栏“模拟账户”入口选择账户类别。训练会话可选默认模拟或自营练习；实盘重演仅可选默认模拟，自营练习不自动改变会话用途。选择自营练习时选择启用模板，规则与成本摘要可按需展开，手续费与滑点输入始终展开。自营实例、规则快照、会话账户类别和原模拟账户原子保存。

账户从创建时的当前源序号之后开始记账，不回填此前已浏览行情，不改变会话进度、风险偏好或关卡。模板规则和权威源日历在此时快照，创建失败整体回滚；重复或并发创建最多成功一次。原有自营会话的重新开始仍保留原类别和固定规则，兼容既有会话及创建接口。

### 回放、出金和归档

界面面向桌面浏览器，不以手机布局作为交付要求。工具栏“模拟账户”集中展示账户信息，原交易操作通过独立的“交易”按钮进入；未创建账户时提示先创建，原下单控件和关卡交互复用。

自营账户标题使用模板名称，摘要显示账户余额、账户权益、亏损底线、剩余回撤额度、交易指标及考核进度或出金可提额度；默认模拟保留原摘要。工具栏同时显示账户余额及阶段徽标，考核中为蓝色、通过考核为绿色、出金阶段为金色，配合文字和边框表达状态。

“规则快照”“日终账本”“账户事件”和“申请出金”按阶段在账户入口分别提供；规则快照只聚焦两阶段规则、原账户配置与账号成本。桌面弹窗采用紧凑分组和受视口约束的滚动区，不依赖无限增高。

风险金额旁的齿轮设置会话级默认规则：固定金额或用户填写的余额百分比。设置只影响新订单草稿的默认风险预算，当前草稿可按原入口调整；不新增数量公式，不因晋级、出金或重新考核重置偏好。禁止交易时，在图表布置订单入口提示具体原因，服务端仍重新校验。

出金确认显示申请、实得、扣款后余额、底线和当日暂停说明。本轮失败显示触发时源序号、观察权益、底线、阶段和累计实得；明确说明持仓已自动平仓且挂单已撤销，提供“重新考核”和完整历史入口。失败平仓进入历史表格、图表标注和导出；历史记录标明轮次。

会话列表展示账户类别、当前阶段 / 结束结果、累计实得。归档详情仍可按既有规则查看图表、日志和注释，并新增规则快照及出金流水。

固定文案由 `lib/i18n.ts` 的 `copy` 统一导出，自营文案分文件维护；金额复用 `lib/format.ts`，确认使用 `ConfirmDialog`，交付按桌面 UI 规范检查。

## 7. 数据和实现职责

`lib/prop-practice/rules.ts` 负责账户纯规则，`service.ts` 负责事务与业务编排，`rounds.ts` 负责轮次和重新考核。现有 engine、risk-sizing、training-gate 的业务算法不因账户类别变更。组件负责展示与交互，API 校验请求并调用统一业务服务，不复制规则。

| 数据 | 职责 |
| --- | --- |
| 模板与当前规则 | 配置、启用状态、schema 版本、内部并发修订号；未使用模板修改时替换规则记录，不保留修改历史；已有引用的历史记录保留 |
| 会话账户类别 | 旧会话及未建账户会话默认为 STANDARD；首次创建自营账户时原子绑定 PROP_PRACTICE，账户创建后固定不可切换 |
| 自营实例与轮次 | `PropPracticeAccount` 保存当前轮次身份和规则状态；`PropPracticeRound` 保存各轮执行结果、规则 / 关卡快照、起止源序号及结束证据；提款和事件按轮次归属 |
| 账号成本快照 | 购买金额、激活费用及对应币种，保留未填写状态；作为用户钱包扣款依据，不改变自营交易盈亏公式 |
| 用户钱包与费用流水 | `lib/user-wallet/service.ts` 维护可用余额、按会话和轮次去重的购买 / 激活费用，以及按出金记录去重的实得入账；不将自营阶段初始资金当作用户钱包存入 |
| 阶段记录 | B0、起点 rawNet、阶段位置、高水位、追踪项、永久底线；不改变原交易状态 |
| 账户日记录 | 日初 rawNet、日终余额、日净利、成交及结算状态，以及盘中考核阶段结束标记；考核统计成交日与最大盈利日，出金按规则统计合格盈利日，阶段保存最近成功出金日作为下一出金统计周期的计数起点；保留完整历史，不保存日损额度或日损基准 |
| 出金流水 | 申请、分成、实得、前后自营余额 / 底线、源位置、请求幂等键 |
| 账户事件 | 晋级、出金、等待、恢复、失败、重新考核、归档及对应轮次和证据 |

同一轮的考核转出金不增加第二个底层账户、不切换 projection、不清空交易，也不修改该轮原累计统计；自营账本通过阶段锚点与出金流水表达。重新考核是另一种操作：为新轮建立独立账户和 projection，将当前身份切到新轮，旧执行结果全部保留；旧页面的订单、推进或写请求不能写入新轮。

模板、预览、确认等 API 都需服务端校验；账户可用性在会话边界检查，不能只禁用按钮。原下单 API 的价格、数量、订单类型及关卡校验原样执行，不附加新的订单规则。

资格查询、预览与打开弹窗不落账。只有成功操作更新账户状态、版本、流水和命令；并发请求、重试和恢复必须得到相同结果。

当前规则使用 `schemaVersion: 2`：`evaluation` 保存考核条件，`funded` 保存出金风险和可选的 `qualifyingDays` / `qualifyingProfit`，阶段状态以 `qualifyingAfterDay` 记录最近成功出金日。这些状态使用既有 JSON 文本列。早期开发快照兼容性决定见开发日志；程序不自动删除或改写旧模板和会话，不能把早期重建决定套用为以后升级时丢弃数据的许可。

规则与已有命令 / checkpoint 一起保存。账户轮次由 `PropPracticeRound` 独立记录，每轮关联自己的执行结果；结果身份同时用于拒绝旧页面写入。结束结果不会被纠错清理流程删除。v1.0 的轮次迁移保留原会话、账户和日志容器，为提款与事件增加轮次归属，旧记录仅归入第 1 轮，不补造历史重置；后续数据库变更按 [AGENTS.md](../../AGENTS.md) 与[升级指南](../operations/upgrade.md)的基线及新入口规则执行，不继续向旧兼容脚本追加迁移。

## 8. 示例

通用模板：两个阶段初始资金均为 50,000，EOD 追踪额度均为 2,000；考核底线封顶 50,000，出金底线封顶 50,100。

考核要求净利 3,000、至少 2 个成交日、50% 一致性。本例出金阶段关闭合格盈利日要求，不设普通交易日、周期最低净利润或周期一致性要求；最低申请 500、可提剩余利润 50%、单次上限 2,000、保留利润 2,100、分成 90%。

原交易系统两日分别产生净利 1,500，日终空仓且无挂单时通过。考核历史终值 53,000 保留，自营出金阶段从 50,000 开始；底层累计交易结果、关卡和数量规则均不重置。

出金阶段后续累计净赚 5,000，自营余额 55,000，底线 50,100。比例上限 2,500、单次上限 2,000、缓冲允许 2,900，可提上限为 2,000；本例未开启合格盈利日规则，累计利润花了几天取得不影响申请资格。若开启 N = 2、W = 100，则必须有 2 个已结算且有成交、日净利润至少 100 的出金阶段交易日；成功出金后计数归零，保留旧日账本与未提利润，下一出金统计周期需重新达到 2 日；这不会新建账户轮次。

申请 1,000，扣减自营余额至 54,000，实得 900，当日暂停。后来某根源 K 完成或原用户操作完成后，观察权益达到 / 低于底线，冻结本轮并暂停，会话保留；主标识为“成功出金 $900”，详情保留规则失败证据及自动平仓成交、日志和最终权益。

## 9. 验收与回归标准

- 不能修改原撮合、订单、风险金额计算或关卡算法来适配账户规则；风险预算偏好只生成原流程的输入，不改变数量算法。
- 相同原账户输入与相同合法操作序列下，账户允许交易期间，逐源 K 的订单、成交、持仓批次、原盈亏 / 费用、OCO 和关卡结果与原流程完全一致；账户层在完整结果之后判断风险。触发失败时，另复用当前价格平仓流程追加必要平仓结果并撤单，不回改此前成交。
- 覆盖用户当前价格平仓、反手、保护单同根触发、关卡自动触发 / 完成，确保未加新订单校验或重置关卡。
- 默认模拟的创建、费用、数量、训练 / 实盘重演和已有会话完全兼容。
- 回撤模式只允许静态 / 日终余额追踪；不再保存或执行逐源 K 收盘权益追踪模式，日终模式不因普通源 K 或用户平仓盘中抬高底线。
- 两阶段都没有每日亏损失败线、日损暂停或隐藏日损校验；每日亏损不会被误判为独立的失败原因。
- 风险仍按声明的完成快照精度检查，K 内触线再恢复不被误写为已精确识别。
- 账号成本的购买金额与激活费用能分别保存，0 和未填写可区分，已有账户保留固定快照；费用不改变自营阶段余额、权益、盈亏、可提额、累计实得、风险或关卡，但须验证用户钱包的购买、重新考核和手动晋级扣款、余额不足整体回滚及请求幂等。
- 激活费用缺省、0、正数均能正常保存和创建会话；缺省不会阻止考核通过及进入出金阶段，不会被补成默认费用。
- 两阶段失败均在同一事务中自动全平、撤销全部待成交单并保存日志与失败状态，不自动归档会话，不删除本根已有成交。重复请求不重复平仓；任何一步失败都整体回滚。重新考核创建新轮并保留全部旧轮。
- 阶段初始资金、利润锚点与出金流水隔离；提款不伪造盈亏、连亏、考核成交日或一致性统计，也不降低风险底线。
- 考核不提供或隐式校验最少合格盈利日数、单日合格净利润门槛；最少交易日只按实际成交日计数，一致性仅按比例判断，不额外叠加固定盈利日数条件。
- 申请 1,000、90% 分成仅扣 1,000，实得 900；先算首次提款底线，不能超提。
- 出金可选校验合格盈利日；只计已结算、有实际成交且日净利润达标的不同交易日，每次成功出金后重计，失败申请与重试不能重置或重复计数。不开启时，次日无新增盈利但有可提剩余利润仍允许申请。
- 出金不提供或隐式校验普通最少交易日、周期最低净利润、周期一致性。
- 批量与单步、快进与逐根、重启与连续运行结果相同；源周期 / 显示周期切换不改变业务结果。
- 日切、隔夜、夏令时、缺失行情、数据结束、并发与重试不造成漏归档、重复计数或重复出金。
- 日末有仓后在同源 K 按原入口平仓，更新同一日费用和净利润再判断晋级；跨日补结算先于新日首根，晋级后该首根不丢失、不多等一天。
- 手动当日切换覆盖当前日成交日与一致性、已实现净利润扣费、空仓/无挂单/失败校验、同日分阶段账本、出金合格日隔离、并发幂等、陈旧请求拒绝、事务回滚及单步/批量推进一致；原日终自动晋级继续有效。
- 一致性覆盖恰好等于比例、最大盈利日同日增长、第三日补利润、费用及显示取整；不得以金额显示四舍五入放宽资格，也不隐式加入机构缓冲。
- 多轮覆盖两阶段失败、空仓 / 持仓失败自动平仓、下一源 K 起步、并发幂等、事务回滚、旧请求拒绝、原关卡与风险偏好保留及累计实得隔离。
- 历史交易不可继续执行；旧轮 / 当前轮 / 全部轮次视图的绘图与会话重命名继续按会话权限工作，无效轮次、错误结果身份及纠错锁不能绕过。
- 出金当日禁止下单但允许行情连续推进，下一源交易日恢复；模板引用限制、账户创建入口和桌面交互按当前界面核验。

## 10. 当前限制与待确认事项

- **自动晋级激活费尚未接入：** 当前日终自动晋级经 `lib/prop-practice/rules.ts` 的 `settlePropDay` 和 `lib/prop-practice/service.ts` 的 `persistPropAccount` 保存阶段、事件与成长记录，没有调用 `chargePropActivation`；手动确认路径 `confirmPropPromotion` 已在事务中调用。现有钱包生命周期测试验证的是手动晋级扣费，不能当作自动路径已覆盖。此差异与界面的概括提示不一致，需后续代码修复及验证；本次仅记录现状，不将其固化为自动晋级免费规则，也不补扣历史费用。
- 风险只观察原引擎完整源 K 或用户操作结果，不能识别源 K 内触线后恢复的瞬间，不承诺复刻机构真实盘中风控。
- 默认仅支持正数初始资金、静态 / 日终余额追踪和当前声明的完成快照精度；没有真实资金、券商连接、自动付款或合约专用计价。
- 一致性当前为无业务缓冲的可配置比例模型。Lucid 等机构的特有 cushion 属于已调研但尚未确认采用的差异，不将表格示例反推为固定金额或固定百分比配置。
- 后续引入机构专属规则时须另行明确范围和公式，再同步本文、实现及测试；不据调研发现自动修改已有账户快照。
- 历史测试数字、部署和服务状态保存在分阶段实施记录或开发日志，不构成当前版本已验收的结论。桌面视觉、真实使用步骤与重置后的历史体验应单独验收。
