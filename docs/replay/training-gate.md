# 模拟训练交易关卡

> 文档状态：当前规范。适用范围：当前交易关卡配置、默认值、计数与复盘规则；深化设计快照仅供追溯。

本文维护当前自动开启配置、交易计划模式和复盘承接规则；2026-10-23 的设计背景见 [交易关卡深化设计快照](training-gate-v2-requirements.md)，其中旧默认值不作为当前配置依据。

关卡入口位于回放标题区、模拟训练标识左侧；网页全屏时移入顶部工具栏。
持续笔数默认 10，自动开启默认关闭，下一轮模式默认选择交易计划。可在未开启时保存配置或立即开启，也可调整连续亏损触发笔数和下一轮模式。已有会话显式保存的配置继续沿用，不批量改写数据；缺少配置项时使用当前默认值，旧版运行中关卡仍按原清单模式完成。关卡运行中没有关闭入口，配置只读。

## 下单和记录

- 右键创建订单草稿，先调整入场、止损、止盈和风险参数。关卡开启时，最后一步按本轮模式完成策略清单或交易计划。
- 策略清单模式下，检查弹窗全部勾选后才能确认；更换策略清空勾选，取消保留草稿，提交成功才清除。交易计划模式下按每步二选一的路径判断到六类背景之一，再写一段非空计划即可确认，不要求 Setup 或清单。背景判断图悬浮或聚焦时显示，离开图标与图片区域或失焦后关闭；点击不固定图片。
- 已提交挂单的价格、数量和风险参数修改沿用原检查快照。撤单后重新创建入场订单要重新检查。
- 相反方向且数量不超过当前持仓的市价、限价或止损单自动识别为减仓/平仓，保存为 `reduceOnly`。它们免检查、不计入关卡，不会因持仓变化或改单而反向开仓。
- 入场确认时的清单或交易计划快照随 FIFO 仓位批次进入日志。日志策略可事后修改，原检查记录不可覆盖；交易计划模式首次生成日志时直接写入复盘正文，之后用户编辑不会被重建覆盖。

## 计数与恢复

- 开仓、加仓和反向入场每次实际成交计 1 笔，挂单提交及撤单不计数。
- 每次入场的仓位全部平完后，将所有分批平仓收益和分摊手续费汇总为一次净盈亏结果；滑点已体现在实际成交价中。
- 关卡未开启且自动开启已启用时，连续亏损达到配置笔数（默认 2）自动开启。盈利/保本打断连亏；关闭自动开启或改变阈值会清零触发计数。运行中的关卡不会重复开启或延长。
- 开启时撤销未经检查的入场挂单，保留平仓单、保护单和已检查挂单。若一笔反向单平掉第二笔亏损，只执行其平仓部分，未经检查的新仓需要另行提交。
- 完成关卡后清零触发用连亏计数；账户原有盈亏统计口径不变。
- 关卡随训练会话独立保存。刷新、切换保留进度；原会话重新开始保留开启状态和配置并从零计数。自营账户的“重新考核”仍在同一会话，只新建账户轮次，关卡开启状态、连亏和完成计数原样保留。自动与手动开启都使用预设的下一轮模式，并在本轮锁定。实盘重演不使用关卡。

## 存储与校验

迁移 `20261014160000_add_training_gate` 添加策略清单及版本、会话关卡状态、订单/批次/日志检查快照、未平完批次的累计净盈亏。SQLite 初始化脚本支持重复执行。

旧会话不追溯过去已经结束的亏损。旧的未平完批次首次读取时，从原入场成交和已有平仓日志补齐累计净盈亏，然后正常参与之后的结算。

会话接口 `/api/replay-sessions/[sessionId]/training-gate` 支持 GET、PUT、POST。新订单的检查项与策略版本由服务端验证；服务端同步从已保存订单和真实源 K 线重新验证关卡及日志快照，不接受客户端伪造的审批或进度。
