## 2026-10-28：两阶段失败自动平仓

按用户最新确认，考核阶段和出金阶段失败均自动在最后已处理源 K 收盘价执行市价全平，沿用既有滑点、手续费及 FIFO 流程；同时撤销全部待成交挂单，原子保存成交、日志、权益、关卡和失败状态。触发失败的原始权益/底线证据保留，最终余额与指标包含平仓成本。普通推进、批量/高周期推进、跨日前结算和当前价格平仓操作共用新失败提交入口；已自然平仓不重复执行。申请出金与主动归档规则不变。无需数据库字段或迁移变更，不回填既有开发数据。

验证：9 个相关测试文件共 215 项通过，覆盖两阶段失败、逐源/同步/高周期提前停止、跨日结算在上一已揭示源 K 平仓、当前价格部分平仓费用致失败、保护单已平仓不重复、剩余开仓单撤销、成交/日志/失败事件三处故障回滚、请求重试与连续重新考核。Lint、TypeScript 和差异检查通过。测试使用临时合成数据库，未改写实际开发库，未运行生产构建或 Computer Use；提示文案的实际外观按用户约定自行验收。

## 2026-10-24：账户卡片只显示当前阶段统计

用户反馈转为出金后卡片“已实现盈亏”仍显示考核成绩。确认原卡片混用了阶段资金与整轮原账户指标，资金并未错误转入出金阶段。现按用户确认将已实现盈亏、手续费、最大回撤统一改为当前阶段；考核历史和底层累计值保留，默认模拟口径不变。

- `lib/prop-practice/stage-metrics.ts` 集中纯函数：独立的已实现盈亏/费用锚点、权益峰值和最大回撤；晋级初始为零，从原完成结果持续更新。统计权益排除提款，实际风控仍按扣款后的资金和原规则执行。
- 原观察入口仅补传累计已实现盈亏和费用，未修改撮合、风险数量、费用、OCO、反手、当前价格平仓或关卡算法。阶段 JSON 保存新增指标，不新增 Prisma 迁移，不对真实库执行升级。
- `stage-metrics-read.ts` 为已有账户按原成交和分块源收盘数据只读还原当前阶段。区分源 K 整体结果与同 K 当前价格平仓，不依据稀疏权益样本推断最大回撤；GET 不回写，正常操作沿原事务持久化后继续增量维护。
