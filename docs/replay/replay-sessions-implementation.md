# 回放会话与纠错：当前规则

> 文档状态：当前规范。适用范围：当前会话隔离、训练与实盘重演、纠错及兼容边界；文件名中的 implementation 不表示历史实施报告。

状态：当前规范，整理日期：2026-11-03。本文维护会话隔离、训练 / 实盘重演及 API、存储的兼容边界；文件路径保留以兼容已有引用。升级数据库前按 [升级指南](../operations/upgrade.md) 核对目标库并备份。实施过程及当时验证见 [2026 年 10 月历史日志](../logs/2026-10.md)，不作为当前部署状态证明。

## 会话规则

- 一份行情可有多个独立会话；创建后模式固定为训练或实盘重演。行情由数据集共享，进度、账户、订单、成交、交易周期、日志、统计和绘图按会话隔离。
- 训练保留过程，不允许回退状态或删除单个持仓周期；重新开始会归档旧训练会话并创建新会话。实盘重演使用本地回放撮合，不连接券商，也不导入真实成交覆盖。
- 自营练习增加独立的账户轮次：最大回撤失败按当前自营规则结束本轮，会话保留；“重新考核”创建新轮且从下一源 K 继续，原轮成交、复盘、订单和结束证据保留，关卡进度与风险偏好不变。此操作与上条“重新开始”不同，详见[自营练习设计](prop-practice-account-design.md#21-失败后的重新考核)。
- 完整持仓周期从净持仓为空开始，到再次回到空仓结束；持续反手仍属于同一周期。实盘纠错回到目标源 K 线撮合结束、用户操作前，并原子恢复账户与记录。
- 纠错在后台分块重建，按预览、确认流程替换当前结果。取消、失败或中断保留原状态并清理临时预览；旧页面或其他会话的写入须由会话身份、projection 与版本校验拒绝。
- 回放推进按源 K 线序号撮合。批量保存进度、账户、订单、成交、交易周期、日志与权益采样应保持原子性；重试沿用请求编号与请求内容，响应丢失不能重复成交。绘图和显示周期变化不得改动撮合规则。

## 多窗口回放

- 可交易回放在顶部工具栏右侧显示当前布局的图标，和「重置进度」之间用分割线隔开。布局菜单按窗口数分行展示 1～5 窗的图标选项，保留悬浮提示和无障碍名称。固定窗口身份随布局保留，窗口 1 始终是主窗。拖拽或聚焦分割线后可用方向键调整比例。布局和各模板比例保存在浏览器，空间不足或进入日志回看时临时显示主窗。
- 点击图表区域或聚焦标题按钮后，公共周期、显隐、指标、图表样式和绘图工具作用于该窗。趋势线、斐波那契、AB=CD、矩形和文字的创建快捷键也作用于当前激活窗。用 Alt + 左键或标题按钮最大化和恢复；播放栏仍服务同一回放会话。副窗周期按数据集及窗口记忆，指标、显隐和图表样式按浏览器窗口编号记忆。副窗从已有合法快捷周期挑选未使用周期，数量不足时使用主窗周期。
- 播放、定位、撮合、账户和会话保存仍由一套引擎处理。「下一根」及其快捷键固定按主窗周期推进。副窗按相同已确认源序号和 ETH／RTH 边界读取有界行情，并尽量用共享缓存中的已确认源柱更新形成柱。副窗行情错误可在对应窗重试。图上交易操作仅主窗提供；副窗显示同账户订单、持仓与成交。
- 各窗独立缩放和平移，图表工具按激活窗操作。绘图隔离见[会话绘图持久化](../charting/archived-drawings.md)。AI 取图及 PDF 当前图表偏好使用主窗。
- 副窗查看历史行情时保持原视口。批量推进或缓存缺口使新旧窗口不连续时，独立更新最新行情，图表继续显示正在查看的窗口。回到右端或重置图表视图后恢复跟随最新行情。进入日志回看后仍可切换其他日志，恢复多窗时控件始终指向可见窗口。

## 历史只读逐根回放

- 历史页复用 1～5 窗布局、激活窗工具栏、分割线和单窗最大化。历史页默认单窗，独立记忆布局、比例和各数据集的副窗周期。各窗可以独立缩放、平移和切换显示周期。RTH／ETH 控件作用于全部窗口。打开交易时，各窗从该交易的入场源序号定位，绘图按原会话的固定窗口编号读写。
- 从任一窗口启动逐根回放，所有窗口共用同一个已揭示源序号，步进和自动播放间隔按主窗周期计算。高于主窗周期的副窗用当时段内已揭示的源柱显示和更新形成中 K 线，收盘后使用完整柱。形成柱只读取到共享源序号；快速推进时副窗合并等待中的更新，随后跟上最新位置。更新失败和重试期间保留最近成功读取的同柱快照。各窗按本窗最后一根实际显示的柱跟随，手动平移后保留视口。静态隐藏和恢复同样作用于所有窗口。
- 历史图表支持与实时回放共用的网页全屏，保留标的、只读上下文、头像和图表工具；按钮与 Escape 可退出全屏，菜单、弹窗及绘图交互优先处理 Escape。
- 历史右键菜单第一项为“重置图表视图”，图表空白区也可使用；复用实时回放的默认缩放与价格自动缩放，定位到当前已揭示的最后一根 K 线，不改变隐藏边界、播放游标或成交与绘图。步进或切换窗口期间，菜单项暂时禁用并提示原因。等待重置加载时，后续手动操作图表会取消这次定位。
- 历史行情终点取所选会话实际已回放到的源序号，包含最后平仓后的已练习空仓行情；已结束的自营轮次使用该轮次冻结的结束序号，不能借用后续轮次或其他会话的进度。顶部范围显示实际终点，进入某笔交易只改变初始定位。起点前仍可提供观察背景的窗口行情。
- 右键真实可见 K 线选择“从此处回放”：保留选中柱、隐藏后续价格与成交量，初始暂停。底部提供播放 / 暂停、下一根、速度和“退出回放”，不增加日期定位、交易记录或交易操作。每次揭示一根主窗显示周期的实际聚合柱，窗口截断造成的形成中尾柱须先补齐后再揭示，仅历史终点允许保留部分柱；缺失行情不补造；自动播放间隔为主窗周期秒数除以速度倍率，倍率沿用 1–100。Ctrl / Command + ↓ 切换播放，Ctrl / Command + → 推进；输入、菜单及弹窗期间不触发。
- 历史图表对支持双时段的标的提供与实时回放共用的 RTH / ETH 控件；仅当前页面切换，不回写原训练设置。切换时段或显示周期先暂停，保持原源序号边界。所有受影响的可见窗口行情和首个所需形成柱读成功后才切换；读取失败保留旧周期、旧时段、旧行情和边界并允许重试。跨越边界时，高周期副窗显示形成柱，主窗及其他窗口待该柱完整揭示后显示。播放和手动步进串行，后台自动暂停，到最后可显示柱自动暂停。RTH 下无后续柱时，切换 ETH 后可继续查看同一历史范围内剩余夜盘行情。
- 历史“指标”面板包含共用的“K 线倒计时”开关，沿用浏览器显隐偏好与总指标开关。逐根回放期间在最新已揭示柱右侧显示距下一根揭示的实际剩余秒数，和播放定时器共用截止时间，速度变化后重新计时；暂停、后台、读取行情期间、退出或到达终点时隐藏。实时回放仍沿用当前形成柱的源行情剩余时间语义。
- 历史成交标记、绘图和文字保留，沿用既有显隐偏好；成交信息可能包含后续结果，由用户自行控制隐藏。指标仅计算已揭示价格。原有“隐藏后续K线”仍可单独使用；逐根回放期间选择它会暂停并转为静态隐藏。
- “退出回放”停止播放、取消在途请求并清除隐藏边界，恢复该历史范围全部 K 线，未载入部分继续按窗口读取；连续播放沿用历史窗口根数上限，压缩窗口时合并已有预热区与移除的前缀，保留指标所需的前置数据。刷新或重新进入恢复普通历史视图，不保存逐根重看的位置。此功能只维护页面内的观察游标，不写训练进度、账户、订单、成交或统计；历史绘图仍沿用原自动保存规则。

## 图表样式与显示边界

- 实时回放、历史只读回放和网页全屏共用“图表样式”：K 线图保留既有配色预设及主体 / 边框 / 影线设置；折线图仅选择收盘价或开盘价和线条颜色，默认收盘价、蓝色 `#2563EB`、2 px 实线，相邻已存在时间点直线连接。切换类型不自动覆盖任何自定义颜色，两种主题各沿用用户已选值。
- 选择即时预览；确认才保存，取消、Escape 和关闭恢复面板打开前的完整配置。切换类型保留两种图形各自设置、同一图表实例、时间视口和跟随状态、绘图选择、订单草稿、订单 / 持仓线及已挂载标注和指标；依赖主价格序列的 primitive 解绑后重新挂载并恢复数据，事件订阅不能重复累加。
- 折线点来自当前显示周期已聚合柱的 open 或 close；形成中的 close 随已揭示源行情更新。沿用原时间点、缺失柱及隐藏边界。切换显示周期时按[历史只读逐根回放](#历史只读逐根回放)的规则处理跨界聚合柱，隐藏部分只保留无价格时间占位。
- 类型和价格来源只影响主价格图形。EMA、ABR、Bar Count、成交量、成交标注仍使用原 OHLC / 源行情规则；撮合、进度、持仓盈亏与订单方向判断继续使用原真实价格，开盘价折线不得代替最新真实收盘价。
- 旧浏览器默认显示 K 线图；既有 `market-replay-candlestick-style-v1` 六色及可见性偏好不迁移、不覆盖。新增版本化 `market-replay-chart-display-v1` 只保存 `chartType` 和折线 `priceSource / color`，统一页面配置在内存组合既有 K 线偏好。非法值回退 K 线 / 收盘价 / 默认蓝色；存储不可用时仍允许当前页预览与切换。本功能不新增数据库字段或交易 API。
- PDF 与 AI 图像继续按既有独立浅色 K 线渲染。页面图表类型及折线偏好不进入导出冻结配置、图片哈希或渲染版本；相关规则仍见 [PDF 规范](replay-pdf-export.md)和 [AI 图片契约](../ai/ai-chart-images.md)。

### 隔离验收入口

[`/preview/chart-style`](../../app/preview/chart-style/page.tsx) 仅在 `USER_GROWTH_PREVIEW=1` 时开放，使用[真实 ReplayChart 与设置面板](../../components/market-replay/chart-style-preview.tsx)及合成已揭示行情、浏览器内存账户，不加载用户、AI 或 PDF Provider，不请求业务 API。验收应使用独立端口与输出目录，并将 DATABASE_URL 指向不存在的专用临时文件，不能使用真实账户或数据库。

预览提供两主题、实时 / 历史只读、网页全屏、历史右键逐根回放与退出恢复、源柱推进、形成中价格更新、显示周期切换、手动平移和重置、绘图工具、预置绘图 / 订单 / 成交标注 / 指标；右键可建立本地订单草稿。诊断区仅在该隔离入口展示配置、真实收盘、折线点价、源序号、持仓盈亏与视口，正式页面不展示实现细节。配置刷新恢复使用实际偏好 Hook；订单 / 成交操作只改变预览内存，不模拟真实交易服务或持久化。
## 历史交易日志日历

- 历史日志支持表格和月历，默认显示表格。月历沿用所选回放会话、自营轮次和已应用的日志筛选，首次打开定位到最新已回放月份。月份选择和前后翻页限于所选范围的首末已回放月份，超出范围的请求返回最新可用月份。
- 笔数按已平仓的 FIFO 日志行计算，交易归入平仓所属交易日。日历使用标的完整交易时段的交易日口径，跨夜行情按该交易日归属。每天与每周均展示交易笔数和手续费前净盈亏，金额按成交价差乘平仓数量统计。每周按周一至周日合计，包含月历上可见的跨月日期。
- 有符合当前筛选条件的平仓记录时，日期链接指向当天最早平仓的交易，平仓时间相同时按内部交易编号排序。日期和交易编号共用历史回放入口，图表定位到该笔交易的入场 K 线。零交易日只显示日期。返回日历时恢复会话、轮次范围和月份。
- 有交易的日期和周汇总按日志的胜负结果展示止盈、止损及打平笔数。
- 月历查询和日期归属使用同一交易日边界。归档自营会话的月份范围与查询的日志轮次一致。月份或筛选切换后，日期跳转随本次统计结果恢复。

## 图表分批止盈止损

- 新增或修改 TP / SL 成功后直接更新图表，不额外显示保存成功提示；操作失败仍显示错误提示。

- 图表持仓标签、保护线及拖动预览的数量统一显示两位小数；实际订单数量与撮合保留原精度。
- 持仓标签在持仓信息与平仓按钮之间以分隔线显示“盈亏：xx”，使用账户快照中当前持仓的未实现盈亏，保留两位小数；盈利数字带正号并显示绿色，亏损显示红色，按显示精度为零时显示中性色的 0.00，悬停可查看账户币种。

- 已有持仓的保护线显示 TP / SL 手柄、数量、R 与设置入口。从手柄拖出同类型分批线，拖动原价格标签仍修改原线价格；拖动预览显示价格与数量，松手创建，Escape、指针取消或失去窗口焦点均取消。点击手柄、双击价格标签或点击齿轮打开设置；设置内可精确新增分批线。
- 拖动或打开设置前暂停并同步回放，结束后保持暂停。新建及修改从下一根源 K 线生效，不回补已揭示的行情；显示周期不影响触发顺序。当前仅从已成交持仓的保护单创建分批线；未成交入场单和草稿仍沿用原来的单组附带止盈止损。
- 原主线默认按全部余仓退出；新分批线默认采用同步后的当前余仓一半，并保存为固定数量。设置可修改价格、固定数量或全部余仓模式；25% / 50% / 100% 是按当前余仓计算固定数量的快捷操作。
- 各条退出单均只减仓，实际成交量不超过余仓。部分退出后，全部余仓线跟随新仓位。TP 成交后，所有未成交的固定数量 SL 均乘以“成交后余仓 ÷ 成交前持仓”；SL 成交后对固定数量 TP 同样处理。同侧其他固定档位保留原计划数量，仅裁减到余仓上限；手动减仓（包括市价、限价和止损类型的普通减仓单）同时按该比例缩减两侧固定档位。每次实际成交后立即联动，沿源 K 线内的实际撮合顺序逐次计算，保留原数量精度，不按两位显示小数取整。加仓不放大固定档位，撤单与改价不触发数量联动。止盈与止损两侧独立，不将 TP1 和 SL1 配对；全部余仓主线与固定分批线也不按独占份额相加。先触达主线可全平，先触达分批线则主线继续管理余仓。完全平仓或反手时撤销原持仓全部保护单。
- 加仓附带新的止盈止损时，按原规则替换全部余仓主线，同方向固定分批线保留。TP / SL 分批编号以当前方向的持仓为范围，两侧分别从 1 递增；加仓、部分减仓不重置，成交、撤销和拖价不重排或复用已有编号。全部平仓后重新开仓或反手时重新从 1 编号；此编号范围独立于持续反手仍属同一完整持仓周期的统计规则。已有订单及历史成交的编号保持不变。
- 创建、修改、撤销仍校验会话、projection 和账户版本；分批创建入口在活动保护单达到 100 条时拒绝新增，数量与价格上限由 [校验入口](../../lib/validations.ts) 维护。设置失败保留输入，过期或已成交的保护单须重新选择；训练归档与实盘纠错沿用各自限制。
- 成交记录逐次保留真实止盈 / 止损原因、退出档位、数量与成交后剩余净仓位。交易日志继续按 FIFO 入场—退出配对分别记录及统计，不因分批或界面展示而合并胜负。部分保护成交仅累计当前持仓周期的收益与费用，归零才结束周期；关卡仍按原规则在入场批次全部退出后判断连亏。
- 图上历史交易标注继续沿用现有逐日志行的 TP / SL / BE 盈亏语义，不用当前保护线反推历史订单触发原因；真实退出原因与档位见成交记录。

## API 与存储兼容

- 数据集级交易 API 显式使用 `replaySessionId` 绑定回放会话；旧 `sessionId` 仍代表日志会话，不混用。会话专用操作位于 `/api/replay-sessions/:id/...`。
- 交易写请求带 `X-Replay-Projection`，防止纠错后过期页面写入。纠错确认更新当前结果；内部身份与显示编号分离，回退/删除后显示编号可重新连续排列，旧链接不得误指向新交易。
- 历史会话迁移保留原记录，不补造无法证明的历史字段；后续数据库变更遵循 [AGENTS.md](../../AGENTS.md) 的版本基线与新升级入口规则。
- 分批保护单复用既有订单结构：有 `ocoGroupId` 的保护单管理全部余仓，未分组保护单按固定数量执行；不新增列或迁移。分批创建沿用 ORDER_CREATE 命令，数量模式修改写入 ORDER_UPDATE，检查点与纠错重建保留相同语义。新增入口为 `POST /api/market-datasets/:id/paper-session/partial-exits`，接收 `sourceOrderId / price / quantity / expectedVersion`；既有改单入口增加 `quantityMode: ALL | FIXED`。
- 本文维护领域规则和兼容约束；当前 UI 按 [UI 规范](../ui/ui-guidelines.md) 与相关功能说明核对，不从历史日志恢复旧界面行为。

## 推进响应与诊断

- `replay/advance` 和 `replay/sync` 支持 `snapshotMode: "LIVE"`：无订单或成交变化时省略快照中的 `recentOrders`、`recentFills`、`recentTrades` 并跳过历史查询。省略表示沿用已确认列表，显式空列表表示清空；有变化或未声明 LIVE 时返回完整列表。
- 客户端仅在账户、数据集、账户版本和起始源序号匹配时合并历史，否则按状态冲突停止推进。进度与账户仍在同一事务中提交，重试复用原回执。
- `Server-Timing` 响应头提供阶段耗时，不自动写入服务器日志。`request` 为服务端总耗时；`scope`、`guard` 为会话读取和外层校验；`transaction` 包含等待、处理及提交。`wait` 包含进入最终事务前的等待与重试，不能直接等同锁等待；`commit` 为回调结束至事务返回，不能直接等同磁盘耗时。其余阶段按名称区分快照、写入、规划与聚合；这些阶段有包含关系，不能全部相加。
