# 回放会话与纠错：当前规则

> 文档状态：当前规范。适用范围：当前会话隔离、训练与实盘重演、纠错及兼容边界；文件名中的 implementation 不表示历史实施报告。

状态：当前规范，整理日期：2026-11-03。本文维护会话隔离、训练 / 实盘重演及 API、存储的兼容边界；文件路径保留以兼容已有引用。升级数据库前按 [升级指南](../operations/upgrade.md) 核对目标库并备份。实施过程及当时验证见 [2026 年 10 月历史日志](../logs/2026-10.md)，不作为当前部署状态证明。

## 会话规则

- 一份行情可有多个独立会话；创建后模式固定为训练或实盘重演。行情由数据集共享，进度、账户、订单、成交、交易周期、日志、统计和绘图按会话隔离。
- 训练保留过程，不允许回退状态或删除单个持仓周期；重新开始会归档旧训练会话并创建新会话。实盘重演使用本地回放撮合，不连接券商，也不导入真实成交覆盖。
- 自营练习增加独立的账户轮次：最大回撤失败按当前自营规则结束本轮，会话保留；“重新考核”创建新轮且从下一源 K 继续，原轮成交、复盘、订单和结束证据保留，关卡进度与风险偏好不变。此操作与上条“重新开始”不同，详见[自营练习设计](prop-practice-account-design.md#21-失败后的重新考核)。
- 完整持仓周期从净持仓为空开始，到再次回到空仓结束；持续反手仍属于同一周期。实盘纠错回到目标源 K 线撮合结束、用户操作前，并原子恢复账户与记录。
- 纠错在后台分块重建，按预览、确认流程替换当前结果。取消、失败或中断保留原状态并清理临时预览；旧页面或其他会话的写入须由会话身份、projection 与版本校验拒绝。
- 回放推进按源 K 线序号撮合。批量保存进度、账户、订单、成交、交易周期、日志与权益采样应保持原子性；重试沿用请求编号与请求内容，响应丢失不能重复成交。绘图和显示周期变化不得改动撮合规则。

## 图表分批止盈止损

- 新增或修改 TP / SL 成功后直接更新图表，不额外显示保存成功提示；操作失败仍显示错误提示。

- 图表持仓标签、保护线及拖动预览的数量统一显示两位小数；实际订单数量与撮合保留原精度。

- 已有持仓的保护线显示 TP / SL 手柄、数量、R 与设置入口。从手柄拖出同类型分批线，拖动原价格标签仍修改原线价格；拖动预览显示价格与数量，松手创建，Escape、指针取消或失去窗口焦点均取消。点击手柄、双击价格标签或点击齿轮打开设置；设置内可精确新增分批线。
- 拖动或打开设置前暂停并同步回放，结束后保持暂停。新建及修改从下一根源 K 线生效，不回补已揭示的行情；显示周期不影响触发顺序。当前仅从已成交持仓的保护单创建分批线；未成交入场单和草稿仍沿用原来的单组附带止盈止损。
- 原主线默认按全部余仓退出；新分批线默认采用同步后的当前余仓一半，并保存为固定数量。设置可修改价格、固定数量或全部余仓模式；25% / 50% / 100% 是按当前余仓计算固定数量的快捷操作。
- 各条退出单均只减仓，实际成交量不超过余仓。部分退出后，全部余仓线跟随新仓位；固定线只会裁减到余仓上限，不随加仓放大。止盈与止损两侧独立，不将 TP1 和 SL1 配对；全部余仓主线与固定分批线也不按独占份额相加。先触达主线可全平，先触达分批线则主线继续管理余仓。完全平仓或反手时撤销原持仓全部保护单。
- 加仓附带新的止盈止损时，按原规则替换全部余仓主线，同方向固定分批线保留。TP / SL 分批编号以当前方向的持仓为范围，两侧分别从 1 递增；加仓、部分减仓不重置，成交、撤销和拖价不重排或复用已有编号。全部平仓后重新开仓或反手时重新从 1 编号；此编号范围独立于持续反手仍属同一完整持仓周期的统计规则。已有订单及历史成交的编号保持不变。
- 创建、修改、撤销仍校验会话、projection 和账户版本；分批创建入口在活动保护单达到 100 条时拒绝新增，数量与价格上限由 [校验入口](../../lib/validations.ts) 维护。设置失败保留输入，过期或已成交的保护单须重新选择；训练归档与实盘纠错沿用各自限制。
- 成交记录逐次保留真实止盈 / 止损原因、退出档位、数量与成交后剩余净仓位。交易日志继续按 FIFO 入场—退出配对分别记录及统计，不因分批或界面展示而合并胜负。部分保护成交仅累计当前持仓周期的收益与费用，归零才结束周期；关卡仍按原规则在入场批次全部退出后判断连亏。
- 图上历史交易标注继续沿用现有逐日志行的 TP / SL / BE 盈亏语义，不用当前保护线反推历史订单触发原因；真实退出原因与档位见成交记录。

## API 与存储兼容

- 数据集级交易 API 显式使用 `replaySessionId` 绑定回放会话；旧 `sessionId` 仍代表日志会话，不混用。会话专用操作位于 `/api/replay-sessions/:id/...`。
- 交易写请求带 `X-Replay-Projection`，防止纠错后过期页面写入。纠错确认更新当前结果；内部身份与显示编号分离，回退/删除后显示编号可重新连续排列，旧链接不得误指向新交易。
- 历史会话迁移保留原记录，不补造无法证明的历史字段；后续数据库变更遵循 [AGENTS.md](../../AGENTS.md) 的版本基线与新升级入口规则。
- 分批保护单复用既有订单结构：有 `ocoGroupId` 的保护单管理全部余仓，未分组保护单按固定数量执行；不新增列或迁移。分批创建沿用 ORDER_CREATE 命令，数量模式修改写入 ORDER_UPDATE，检查点与纠错重建保留相同语义。新增入口为 `POST /api/market-datasets/:id/paper-session/partial-exits`，接收 `sourceOrderId / price / quantity / expectedVersion`；既有改单入口增加 `quantityMode: ALL | FIXED`。
- 本文维护领域规则和兼容约束；当前 UI 按 [UI 规范](../ui/ui-guidelines.md) 与相关功能说明核对，不从历史日志恢复旧界面行为。

## 推进响应与诊断

- `replay/advance` 和 `replay/sync` 支持 `snapshotMode: "LIVE"`：无订单或成交变化时省略快照中的 `recentOrders`、`recentFills`、`recentTrades` 并跳过历史查询。省略表示沿用已确认列表，显式空列表表示清空；有变化或未声明 LIVE 时返回完整列表。
- 客户端仅在账户、数据集、账户版本和起始源序号匹配时合并历史，否则按状态冲突停止推进。进度与账户仍在同一事务中提交，重试复用原回执。
- `Server-Timing` 响应头提供阶段耗时，不自动写入服务器日志。`request` 为服务端总耗时；`scope`、`guard` 为会话读取和外层校验；`transaction` 包含等待、处理及提交。`wait` 包含进入最终事务前的等待与重试，不能直接等同锁等待；`commit` 为回调结束至事务返回，不能直接等同磁盘耗时。其余阶段按名称区分快照、写入、规划与聚合；这些阶段有包含关系，不能全部相加。
