# 普通推进事务与浏览器重复工作优化

> 文档状态：历史记录。适用范围：2026-10-18 的普通推进优化与本机验证；当时的 WAL 配置与性能结果不作为当前部署指令。

## 实施范围

- 普通推进复用同一事务中已读取并更新的账户、训练关卡和末根价格构造快照，训练持仓兼容补齐只执行一次；账户状态与统计合并更新，进度与幂等回执合并保存，结果进度仅在事务末尾更新一次。
- 比较推进前后的持仓批次，未变化时跳过删除/重建；训练关卡未变化时跳过重写。纠错重建仍保留其原有完整持久化路径。成交、逐源峰值与回撤、稀疏权益末根补点仍在原事务中完成。
- 上下文先在内存中合并相邻相同段，再批量插入；跨请求最多延长已有尾段一次，每次写入最多 500 段。源序号、代数和各段上下文内容保留。
- 浏览器缓存只写本次推进改变的显示 K 线，包含因时间缺口而结束形成的上一根；250ms 内合并同桶修订，按顺序写入 IndexedDB。窗口刷新覆盖尚未写入的旧修订。卸载可丢弃尚未刷新的显示缓存，交易进度已由服务端事务保存。
- 已完整取得的交易标记窗口，在日志数量不变、回放继续向右时复用。向左读取未覆盖范围、新成交、主动刷新、纠错/窗口重载仍会重新读取；截断结果不复用，历史窗口不推断未读取范围。
- 持仓、订单和草稿价格线按稳定身份保留，只在参数变化时原位更新，取消或平仓时删除；保留拖动预览、R 标题与操作坐标更新。

## 前后基准

两组都在本机 Windows / Node 24.15.0、SQLite **3.51.3 / WAL / FULL** 下运行。显式使用应用连接工厂，并断言实际引擎版本、日志模式与 synchronous=2，避免只依赖启动参数推测生效。相同的 5,000 根人工行情、每场景 5 次预热与 30 次样本；串行执行真实同步路由，包含序列化响应，不含 HTTP 与浏览器绘制。

| 场景 | SQL 数量，前 → 后 | 中位耗时 ms，前 → 后 | P95 ms，前 → 后 |
| --- | ---: | ---: | ---: |
| 空仓单根 | 39 → 29 | 59.4 → 48.0 | 107.2 → 50.4 |
| 持仓无成交单根 | 40 → 29 | 48.2 → 48.0 | 87.3 → 59.7 |
| 最近历史较多单根 | 39 → 29 | 59.4 → 47.7 | 153.2 → 66.8 |
| 五根源 K 线 | 39 → 29 | 48.4 → 44.2 | 71.1 → 48.3 |
| 五根上下文逐源变化 | 43 → 29 | 59.6 → 47.9 | 99.1 → 101.7 |
| 一百根上下文逐源变化 | 138 → 29 | 132.6 → 76.7 | 177.7 → 149.3 |

普通单根的 SELECT 从 27 降至 22，UPDATE 从 9 降至 5，且不再删除持仓。100 根变化上下文的 INSERT 从 101 降至 2，其中一条为权益写入。该场景上下文持久化阶段中位耗时约 54.6 → 6.4 ms。

持仓无成交的总中位耗时基本持平；本次磁盘 COMMIT 从 12ms 波动到 24ms，抵消了事务内部节省。五根变化上下文的 P95 没有改善。人工小库、短时样本与磁盘波动不能换算为实际点击或生产环境的固定提速比例。浏览器部分验证了工作量缩减与失效边界，没有给出实测帧率或主线程耗时百分比。
