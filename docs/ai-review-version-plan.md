## 4. 一个全局机器人的使用方式

### 4.1 窗口与聊天

全局只挂载一份 `AiAssistantProvider + AiAssistantLauncher + AiAssistantWindow`，切换页面保留窗口、输入草稿和运行状态。

- 悬浮图标打开机器人，桌面可拖动和缩放，位置、尺寸受视口约束；窄屏使用适合触控的单窗口布局。
- 顶部显示“AI 机器人”、实际生效模型和本次任务，支持最小化、关闭。
- 会话栏提供新建、切换、重命名、清空和删除；聊天会话与交易回放会话分别命名，避免混淆。
- 正文支持 Markdown、表格、来源链接、复制、停止和明确的重试入口。
- 输入区支持中文输入法、粘贴或上传图片，提供“读取当前交易 / 附加图表 / 选择模板 / 总结本会话”等快捷操作；这些不是其他机器人。
- 模板、交易、会话、图表以可移除的上下文标签展示。发送前说明会向哪个端点发送哪些资料，按需附图。
- “清空聊天”只影响所选聊天及其活动运行，不清除正式复盘或已保存报告；清空和删除使用统一确认框。
- 最小化继续运行；关闭取消普通聊天请求并保留输入和已完成消息。会话分析作为独立任务继续，关闭前明确展示其状态与取消入口。
- 每个聊天同一时间只有一个活动生成。切换聊天可查看其他内容，但运行和迟到消息始终归属原聊天。

参考图用于窗口结构和操作方式；配色、按钮、图标及状态沿用本系统的[唯一 UI 规范](ui-guidelines.md)。宽配置窗口因双列表单需要扩展尺寸时，在公共组件集中处理，验证窄屏及内部滚动，不复制其他应用的视觉体系。

### 4.2 单笔复盘

1. 在历史日志中选中交易，或在复盘编辑器使用“交给 AI”；打开同一个全局机器人，附加该笔交易、明确选择的模板和正在编辑的原文。
2. 机器人展示参考交易、周期、时区、图表范围和模板；用户可追加要求，例如“保留我的判断，只完善执行偏差”。
3. AI 返回独立的“复盘草稿 + 详细分析 + 来源 + 待补信息”。草稿按所选模板结构，保持在 2,000 字以内。
4. 用户可继续讨论、要求改写，或点击“采用到编辑器”；采用只更新编辑草稿，最终仍由原编辑器的保存操作提交。
5. 如果用户已修改原文、换了交易或纠错改变了结果，提示比较差异或重新生成，不覆盖当前内容。

支持“从空白生成”和“优化已有复盘”。未选择模板时先提示选择，也允许用户明确使用自由格式；不能静默猜测曾经使用的模板。过长输出提示压缩或手动编辑，不能调用现有 `limitReview` 静默截断 AI 正文。

AI 不能改变成交、订单、Setup、交易理由或检查快照；识别到可能的修正仅作为建议。没有情绪、原计划或动机记录时，使用“未记录 / 待确认”，不能编造。

### 4.3 单会话归纳

1. 用户选择一个回放会话，在机器人请求“总结本会话”；默认覆盖该会话当前有效结果内的全部已结束交易，包括没有复盘的交易。
2. 发送前展示会话、统计单位、总交易数、已写复盘数、排除的未完成交易和图片计划。筛选分析必须明确标为子集，不能把当前表格分页当成整个会话。
3. 程序先计算指标和固定分组，AI 再从笔记及图表提取候选特征，并结合数字、来源和反例组织报告。
4. 报告可保存、查看历史版本和回到相关交易；用户可继续在同一机器人追问。

输出至少包含：范围及资料缺口、做得好的模式、反复出现的执行问题、候选规则、支持与反例交易、下一会话可检验的动作。候选规则与原有正式策略分开，初期由用户查看和手动整理后决定是否纳入策略清单。

## 5. AI 配置与能力管理

采用参考图的端点卡片，允许多个已保存端点、一个当前默认端点。每个端点包含稳定 ID、名称、协议、Base URL、密钥状态、模型列表和默认模型。

- 首个适配器采用 OpenAI-compatible Chat Completions；“兼容”表示遵循相应协议，不承诺所有第三方实现完全一致。支持本地免密钥端点。
- 服务商品牌可作预设，实际能力由协议、配置和测试结果决定，不根据名称猜测视觉、工具或结构化输出能力。
- Base URL 明确包含用户服务要求的版本路径，预览最终聊天和模型列表 URL；高级模式允许分别填写完整 URL。禁止重复拼接 `/v1`，限制 HTTP/HTTPS。
- 允许拉取模型、手工添加和移除模型 ID。拉取失败仍可保存手工模型。截图中的具体名称不作为预装模型承诺。
- 密钥读取只返回 `hasApiKey` 等脱敏状态；留空保留，清除显式操作。“眼睛”按钮只控制本次新输入，不能取回服务端已保存密钥。
- 抽取现有加密算法，建议 AI 使用单独的 `AI_ENCRYPTION_KEY`，不更改原 `MARKET_DATA_ENCRYPTION_KEY` 或行情密文。主密钥独立于数据库保存、随部署备份。
- 文本、图片、工具、结构化输出分别记录“未知 / 已验证 / 不支持 / 测试失败”，测试失败不直接等同于不支持。状态绑定端点配置及模型，修改后失效。
- 保存和打开设置均不自动进行付费探测；测试由用户点击，说明可能产生调用费用。工具探测使用无副作用工具。
- 无视觉能力时可基于结构化行情和文字继续；只有截图时不能伪称已读图。无工具能力时使用服务端预先准备的固定上下文，不声称已检索其他记录。
- 技能配置是任务提示词和模型选择，不是可执行代码。一个机器人内部使用 `globalAssistant`、`chartReading`、`reviewDraft`、`sessionReview`；生成与润色可作为复盘任务的两种模式。
- 技能可编辑提示词、启停、恢复默认和覆盖模型。模型引用必须明确属于哪个端点；切换端点不能把旧端点的模型自动发送到新端点。
- 运行开始固定端点、模型、提示词版本、预算和上下文；中途改配置仅影响新运行。

协议选择是本项目为第三方兼容作的取舍。OpenAI 官方对其新项目推荐 Responses，因此适配层应保留独立扩展位置，不能把 Chat Completions 当作所有厂商唯一接口。[官方接口说明](https://developers.openai.com/api/reference/chat-completions/overview)

结构化结果优先使用已支持的 JSON Schema；无此能力时可接收普通 JSON 后用 Zod 验证，失败则保留为普通回答，禁止直接用于“采用草稿”或正式结构化报告。不进行默认付费修复重试。协议支持 JSON 不代表内容一定符合业务 schema，也仍需处理拒答、截断和中断。[官方结构化输出说明](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)

## 6. 图表、来源和时间边界

每次发送形成固定上下文：`contextId / schemaVersion / capturedAt / analysisMode / replaySessionId / journalSessionId / projectionId / logicalTradeIds / sourceRange / asOfTime / dataVersion / historyVersion / reviewRevision / templateSnapshot / chartSettings / sourceHashes`。上下文含实际有效资料清单、缺失项及截止原因，而不是只记资源 ID。

- 模板与用户当前未保存草稿一起固定；持久化模板 ID、内容摘要及所用正文。模板后来改名或删除不改变已生成结果。
- 交易采用逻辑身份和 projection 定位，显示编号仅作标签。纠错后核对存续记录，不把重新显示为“第 1 笔”的另一笔交易当成原交易。
- 服务端控制行情范围，复用现有聚合、源周期约束和块级摘要；禁止新增完整源行情返回接口。截图和 OHLCV 使用同一份经过裁剪的数据。
- 单笔事后复盘建议默认显示开仓前上下文至本笔平仓，首个实现不默认附加平仓后行情；用户需要观察后续时显式增加范围并标明“事后结果”。长持仓分图而非压成不可读小图。
- 需要解释入场环境时，单独准备截至入场所在源 K 线的图，并说明这是“该源 K 线处理完成后的重建”，不能声称是逐笔成交瞬间的真实视野；当前只有 OHLCV，不能据此恢复真实分时路径。
- 形成中的高周期柱仅聚合允许范围内已揭示源柱，不能用完整桶的最终最高/最低价。EMA、ABR、标记、坐标轴范围和工具返回同样受截止点约束。
- 当前窗口手动画线、DOM 价格标签等不一定都在图表 canvas 截图中。公共截图模块需明确支持项；缺失时说明，不宣称完整复刻当前画面。事后画线不能冒充原入场计划。
- 上传图片是用户提供的参考证据，不能自动证明拍摄时间、所属交易或截止点；提供预览、说明和范围标注。精确数字以验证过的结构化数据为准。
- 首版事后分析可以读取所选交易的结果，但分开陈述“当时可知事实”和“后来结果”。之后扩展训练即时辅导时，禁止注入事后复盘、完整会话报告及未来截图，仅依赖提示词不够。
- 截图不可用时明确降级，不冒充已查看图片。仅发送实际选定资料，不自动重发聊天里所有旧图片。

实现建议提取 `lib/market-replay/chart-snapshot` 公共能力供 PDF 与 AI 使用，业务入口分别决定范围和预算；不让 AI 导入 PDF 文档生成业务。

## 7. 会话分析的统计与可信度

### 7.1 明确统计单位

会话内至少存在 FIFO 日志行、入场批次和完整持仓交易三种单位。分批平仓会增加日志行，加仓和反向交易又影响批次及持仓边界。

建议报告同时显示“日志行数”和“已结束完整持仓交易数”，以现有 `PaperTrade` 的结束记录作为总体盈亏统计主单位；规则对照可使用入场批次，必须标明分母。不要直接把 `cycleKey` 当作全部完整持仓交易的唯一计数依据，需结合现有反向成交转换语义处理。部分批次未平完的结果单列。

- 全会话净盈亏、胜率和连亏复用已验证的交易归并与 `grossPnl - fees` 语义，滑点已在成交价格体现，不重复扣除。
- 日志的 `gainLoss` 是价差口径，不能直接称为净金额收益；报告展示字段单位和费用是否已计入。
- 初始风险和实际不利波动不是同一 R 分母；风险缺失时标为不可计算，不能把界面为了展示使用的最小跳动兜底当成真实初始风险。
- 新增分组指标、费用分摊或批次 R 计算放在独立纯函数中，经与既有账本对账的测试后使用；缺少可靠映射时返回不可计算。
- 最大回撤须明确是账户逐源结果、已结束交易曲线还是采样权益结果，不从稀疏曲线推断精确账户最大回撤。
- 未平仓、无复盘、缺策略和缺风险记录均展示数量；不能仅挑盈利或已写复盘的记录作为“整个会话”。

### 7.2 从归纳到候选规则

先按现有 Setup、方向、时段、交易理由及检查快照等固定维度统计，再让 AI 提取用户复盘中的重复主题。AI 从图形识别的形态、从文字推断的特征标为“模型建议”，与用户确认标签分开。

每个候选规则记录：适用环境、具体条件、支持交易、反例交易、可计算指标、缺失资料、验证步骤和状态。所有引用必须存在于本次允许的来源清单中；数量、均值等来自程序提供的指标 ID。

一个会话内找到的模式属于探索性结果。发现规则与验证规则使用不同样本或后续会话，避免反复搜索条件后在同一批样本自证。首版不提供凭空的置信百分比、不把少量盈利样本说成已证明优势，也不把“盈利”自动等同于“符合原策略”。

保留人写、AI 生成和用户修改后的来源信息；已经采用的 AI 复盘再次参与归纳时，不能被当成独立的人类观察或新增成交证据，避免重复强化模型自己的判断。资料不足时仍可输出整理结果及待补项，但不能包装成已识别可靠交易优势。

## 8. 服务端结构、数据与运行

建议新增 `lib/ai/`，集中维护配置、适配器、技能、上下文、只读工具、运行与存储；会话统计纯函数独立于模型请求。组件不直接连接供应商，不复制撮合或聚合规则。

```text
唯一全局机器人
  → 本地 AI API：校验任务 / 资源 / 版本 / 预算
  → 固定上下文 + 程序计算指标 + 最小只读工具
  → 模型适配器：文本 / 图片 / 流 / 取消 / 用量
  → 校验回答与引用
  → 草稿 / 保存的会话报告
  → 用户采用到原复盘编辑器并手动保存
```

### 8.1 建议持久化对象

| 对象（名称可调整） | 主要内容 |
| --- | --- |
| `AiEndpoint / AiSkillConfig` | 带版本配置、加密密钥、能力测试、提示词及模型引用。 |
| `AiConversation / AiMessage` | 分页聊天、任务身份、来源标签、正文及失败或取消状态。 |
| `AiRun / AiContextSnapshot` | 固定配置与资源范围、状态、预算、实际用量、上下文及来源清单。 |
| `AiReviewDraft` | 正文、证据、缺失项、原文版本和采用状态；不替代正式复盘。 |
| `ReplayReviewRevision` 或等效版本方案 | 同一逻辑交易的复盘版本与内容来源，支持比较和原子条件保存。 |
| `AiSessionAnalysis / AiAnalysisItem` | 会话报告、候选规则、冻结批次清单、检查点、覆盖范围及资料版本。 |

JSON 大字段继续采用 SQLite 当前兼容的 String + Zod，不改变现有 `SimulationRun` 存储约定。截图作为受限文件资源保存，数据库记录元数据和 hash，不把 Base64 混入普通日志。正式复盘仍落在现有 `review` 字段。

复盘编辑与条件保存须覆盖表格内联编辑、原弹窗、AI 采用以及纠错时复盘迁移。建议采用单调修订版本，并在同一事务中比较 projection、逻辑身份及版本后更新；请求 ID 提供幂等。不能依赖当前没有更新的 `ReplayJournalEntry.createdAt` 判断编辑冲突。

### 8.2 只读工具和接口边界

候选接口包括：端点配置与测试、技能配置、聊天与消息分页、上下文准备、运行流与取消、草稿采用准备、会话分析创建/状态/取消/继续及报告读取。具体路由在实施时按现有 App Router 约定确定。

最小模型工具可采用 `get_chart_context`、`get_trade_record`、`get_review_template`、`get_session_review_summary`。行情分页和报告证据读取按需增加；无工具能力时，选定范围由服务端预加载同等资料。

所有工具由服务端白名单注册并验证完整参数，只能读取本次已授权范围；不提供任意 SQL、路径、URL、shell 或通用执行。没有模型可调用的保存、下单或策略修改工具。界面“采用 / 保存”是用户操作的业务 API，不由模型文字触发。

自定义服务 URL 由用户配置并固定到运行，模型不能指定网络目标；第三方密钥不跟随跨域重定向转发。保留用户主动配置 localhost / 局域网端点的能力；写配置和创建运行沿用适当的同源请求校验与参数限制，不引入多用户系统。

### 8.3 运行和长期任务

- 普通聊天有调用次数、超时、输入输出和图片上限；限制在代码中可配置，具体起始数值经选定服务商和样本测量后确定，不能直接当作模型真实容量。
- 流式显示可合并刷新；只在协议完成、结果完整并通过校验后记为成功。断流、截断、拒答、取消和迟到响应有不同状态。
- 停止传递给上游请求和工具；提交结果前再次检查运行状态，防止迟到覆盖。取消不保证供应商停止计费，实际用量未知时显示未知。
- 默认不自动重试付费请求、不自动切换端点。模型服务失败不影响回放、撮合或手动复盘。
- 会话分析先冻结全量资源清单，分页提取及分批归纳，然后汇总；显示实际处理数量、资料遗漏和证据覆盖，不能把小批次结果当作完整报告。
- 持久任务保存检查点和租约，支持取消与显式继续。进程中断后不自动重复状态不明的上游调用；未完成的步骤标记中断，提示重试可能再次计费。
- 批量图片不能无界加载；先逐笔准备结构化资料和特征，按明确预算安排图片。若只分析部分图，报告必须标出，不声称看完全部图表。
- 输入估算、供应商用量和费用估算分开。没有价格配置或上游用量时不伪造精确费用；批任务开始前展示预计规模和上限。
- 回放推进、复盘修改、行情变化和纠错后保留原报告的固定证据并显示适用范围；采用到当前交易时重新校验。纠错替换 projection 后旧报告不可作为新结果的当前总结。
- 当前系统会清理旧 projection。报告可保留独立最小证据快照与失效标记，不为 AI 恢复已移除的交易结果版本功能；不能只存未来会失效的外键。

### 8.4 迁移、备份与部署

实施前遵循[升级指南](upgrade.md)，确认实际数据库和迁移方式并建立一致性备份；Prisma migration 与 `scripts/init-sqlite.mjs` 同步。迁移不完整时，在付费调用前失败，不在业务请求中自动建表。

数据库备份应包含正式复盘、修订、AI 分析报告和证据索引；对应图片文件随存储备份。聊天历史可提供可选导出；普通业务导出不包含密钥。现有独立交易日志 ZIP 不是回放数据的完整备份，不能宣称它已包含新增报告。

保留原行情主密钥，单独备份 AI 主密钥并补充部署环境映射。若会话分析使用独立 worker，必须把 worker 及依赖纳入生产打包，并验证启动、中断和继续；现有升级文档已记录其他 worker 的生产打包缺口，不能只测首页即可交付。

## 9. 实施顺序与验收关口

| 阶段 | 交付 | 验收关口 |
| --- | --- | --- |
| A：模型与唯一机器人 | 配置、密钥、协议适配、技能、持久聊天、流式、停止和窗口。 | 模拟端点覆盖手填模型、脱敏、能力降级、取消、迟到响应；切页面仍是同一窗口。 |
| B：单笔复盘闭环 | 当前交易/模板/草稿桥接、固定图表、生成/润色、证据、采用与条件保存。 | 空白生成和保留原意优化均能完成；2,000 字、并发编辑、切交易、模板变更、纠错冲突均不覆盖用户内容。 |
| C：单会话归纳 | 冻结样本、统一统计、批任务、报告与候选规则。 | 覆盖整个选定会话，分批平仓和反向交易不重复计数；有反例和缺失项；中断恢复不假成功。 |
| D：升级与回归 | 数据迁移演练、备份、部署和使用文档。 | 隔离库保留旧会话与复盘；相关 Vitest、lint、生产构建及 UI 检查通过。 |

A、B、C 属于本次同一大版本目标。不能在 A 完成后把“已接入聊天”说成整个版本完成。研发阶段使用模拟模型、隔离数据库和专用行情；真实端点只在用户主动测试时使用。

关键测试还包括：未来行情哨兵、形成中聚合柱、后写笔记、错误来源 ID、图片与数据错配、跨会话和纠错结果越界、残缺工具参数、取消后迟到保存、超预算、费用与 R 分母、缺风险与无复盘覆盖率、AI 文本来源、任务断点及重复保存。

界面交付遵循 `docs/ui-guidelines.md`，重点检查机器人与复盘弹窗共存时的层级、图表快捷键、焦点、中文输入法、窗口边界和 375/1280/1440/1920px；文案集中到 `lib/i18n.ts`。本节记录规划阶段的验收要求，实施后的验证结果及未验证项目见 [AI 机器人说明](ai-assistant.md)。

## 10. 仍需讨论的产品决定

1. **事后看图范围：** 建议默认开仓前至平仓，平仓后行情由用户显式增加；如希望默认观察平仓后的行情，需要确定根数或时长，并始终区分原决策与事后结果。
2. **“有利”的首要含义：** 建议同时看扣费表现与是否遵守原规则，报告分开呈现；如偏重某一项，可调整候选规则排序，不能据盈亏自动定义纪律好坏。
3. **会话分析的图片覆盖：** 建议支持完整分析模式，超过图片/预算上限时分批继续或缩小范围；可另提供快速文字与统计模式，并明确尚未审阅全部图表。默认使用哪种模式需结合实际会话规模和成本偏好确定。

以上待定项不影响先实施端点、全局机器人和固定上下文基础；本文件中“建议”仍是讨论方案，不表示用户已确认全部细节。
