## 执行与证据

1. 每个已修复问题先加入可复现回归，记录修复前失败与修复后结果；按 P1、P2 顺序独立提交。
2. 使用隔离测试库与测试 fixture，不连接或迁移真实行情数据库，不变更 schema、依赖和配置；保留已有未跟踪交接/审查文档。
3. 逐项测试后运行 `corepack pnpm test --maxWorkers=4 --minWorkers=1`、`corepack pnpm exec tsc --noEmit`、`corepack pnpm lint`、`corepack pnpm run build` 与 `git diff --check`，如失败如实记录，不将历史结果算作本轮通过。
4. Git 只暂存本轮明确文件，每个修复提交包含问题 ID。完成后创建 Fix Report，列出确认情况、根因、文件、命令/结果、风险和实际 SHA。
5. 本轮不引入布局/控件；若客户端状态修复需要改变可见错误文案，复用集中 i18n 与既有错误区域。界面规范已完整阅读，视觉检查未执行时必须说明。
