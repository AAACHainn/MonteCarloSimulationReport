# 行情增量同步

同步跟随 Next.js Node 服务运行，适用于 Windows、Linux、macOS 和容器部署，不依赖 cron、系统任务计划或浏览器保持打开。构建、Vitest 不启动调度器。服务停止后下载停止，已成功发布的分段保留；服务恢复后重新检查未完成分段。

## 配置

1. 在服务器配置 `MARKET_DATA_ENCRYPTION_KEY`，内容为 32 字节随机数的 Base64 编码。可用以下命令生成；将结果作为部署密钥保存，不提交到 Git：

   ```text
   node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
   ```

2. 保持该密钥跨重启、升级不变。缺少或更换加密密钥会使已有 Databento API Key 无法解密，此时需重新保存 API Key。
3. 应用现有外部访问保护必须覆盖整个页面及 API；首版不新增应用登录系统。通过 HTTPS 使用生产网页。
4. 在 K 线回放列表的“行情连接”中保存 Databento API Key 并“测试连接”。界面和读取接口只返回掩码，数据库保存 AES-256-GCM 密文。
5. 在各数据集的“编辑行情设置”中单独设置同步模式、合约口径、频率和美元预算。旧数据集默认关闭。保存设置不会下载行情；点击“同步最新”或者等待下次自动执行。

`MARKET_DATA_SYNC_ENABLED` 默认为启用，设为 `0` 可停止任务处理与自动调度。生产 Compose 从部署环境注入这两个变量；其他部署直接向 Node 服务传入相同变量即可。

## 行为

- 首版同步 Databento CME `GLBX.MDP3` 的 1s/1m/1h/1d OHLCV。成交量连续合约请求 `ROOT.v.0`，指定交割合约请求具体代码。数据源权限制约最新可用时间，“每分钟同步”只是检查频率。
- 下载使用 POST 表单，请求 `continuous/raw_symbol → instrument_id`，再通过免费的 `symbology.resolve` 按 UTC 日期反查实际交割合约；不使用供应商不支持的 `continuous → raw_symbol` 组合。页面错误及任务日志保留 HTTP 状态和安全错误分类，不记录密钥或原始响应体。
- HTTP 合约映射请求使用与下载区间一致的精确 UTC 时间戳。返回映射仍按 UTC 日期解释，但不能把最后一个未结束日期的请求向上扩展到次日零点，否则可能越过本账户许可截止时间。
- `get_cost` 成功仅说明可以估算费用，不能证明较新时段已获许可。以 `get_dataset_range` 返回的本账户可用范围为准；供应商返回 `dataset_unavailable_range` 时显示订阅/许可限制。页面的 UTC 时间需要加 8 小时才是北京时间。
- 手动、自动及中断恢复任务都先查询目标 schema 的本账户可用范围，更新卡片的“数据源可用截至”，再估算费用和下载。本次截止取可用结束时间与当前时间的较小值，并向下对齐到完整 K 线边界。查询失败时不下载；已验证绑定、没有暂停原因且没有新范围时正常完成，不下载。首次绑定或暂停后的重试仍需重叠校验。恢复任务也会收紧旧目标，不会越过新查询的截止时间，后续范围扩展时继续补齐。预查日志使用 `market-sync-range` 记录此次边界。
- 连续规则、价格与成交量必须和本地重叠区间一致。发现修订、额外记录或远端缺少本地记录时保留历史并暂停。通过“最近同步记录”查看冲突；修正绑定后重新校验，首版不自动覆盖历史。
- 按 UTC 日期分段、每批最多 2048 根暂存，完整校验后事务发布。保留旧源序号、账户和回放进度。最多 2000 万根源 K 线。
- 单数据集更新互斥，文件追加与同步不能同时发布。全局同步任务串行执行，刷新页面仍可查看进度。
- 分钟和小时按固定经过时间；日、周、月按计划时区日历计算。月末保留原日期锚点，夏令时重复只执行一次。手动同步不改变自动计划。
- 服务恢复后合并遗漏的计划，不补跑全部历史触发。配置关闭或仅手动时，不因启动创建新下载。
- 使用 Databento `get_cost` 估算并预留美元预算。预算为估算控制，非供应商账单的硬上限；失败下载和重试均可能计费，不自动退回预留金额。0 美元仅允许估算为 0 的请求。
- 已提交分段才推进检查游标；正常无成交不补造 K 线。供应商报告 pending/degraded/missing 时暂停。预算不足、鉴权失败、范围不足等待用户处理；调整配置或手动重试后重新检查。
- 打开的回放每 15 秒检查尾部更新，先提交当前待保存动作，再更新总数及缓存。已结束时保持暂停，不跳到最新，不显示当前序号之后的行情。
- 已有行情解释变化会返回 `HISTORY_CHANGED`，暂停回放并保留页面中的未提交操作，不自动回滚；需要用户核对后重新打开。行情块读取与回放提交均支持尾部追加的历史版本兼容。

## 验证

自动测试使用隔离 SQLite 和模拟提供商，不调用付费接口。真实验收需由用户配置 API Key 与预算后，针对一个 CME 数据集先执行手动同步，再启用定时计划。上线执行 Prisma 迁移，并持久化数据库和加密主密钥。
