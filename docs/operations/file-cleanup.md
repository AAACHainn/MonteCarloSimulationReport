# 文件清理与现场保留

> 文档状态：当前规范。适用范围：开发任务中的文件清理授权、删除前核验及升级/验收现场保留。

执行清理前必须完整阅读本文；全局数据保护底线见 [协作约定](../../AGENTS.md#安全与数据保护)。本文集中维护原协作约定中的清理细则，不扩大自动删除范围。数据库升级、部署及其专项保留要求另须遵守 [升级指南](upgrade.md)。

## 可自动清理的范围

- 默认禁止批量或递归删除；仅对下述已核实范围允许使用 `rm -r` / `rm -rf`、`Remove-Item -Recurse` 等清理命令，无需逐次请用户确认。
- 可自动清理：本任务生成且可重新生成的缓存/构建产物（如项目内 `.next/`、`coverage/`），以及项目 `tmp/` 或系统临时目录下、具有明确创建记录和用途的独立任务子目录（含可重建且无独有改动的构建上下文/源码副本）。历史任务目录须有创建记录或工件清单证明归属本项目且已无保留需求；仅凭目录名、修改时间或被 Git 忽略不足以授权删除。不得整体清空项目 `tmp/` 或系统临时目录，也不得清理其他项目的产物。
- 自动清理例外不包括工作源码/文档原件（含 `tmp/` 中的计划/交接文档）、任何用户改动或用户文件、真实数据库及 WAL/SHM、真实 `.env`/密钥、上传/导入/头像、正式备份和数据卷。独立测试库及随机测试配置仅在确认是本任务生成的合成数据、所有连接已关闭且不属于待保留现场时，可随其任务目录清理。不得为了通过验证而删除数据、重置库或移除升级锁。
- 无法证明归属、范围或可丢弃性时不删除，先列明具体路径和影响，请用户确认；超出上述范围的批量删除须获得用户对明确路径的授权。

## 删除前核验

删除前核对当前工作目录、目标规范化绝对路径、目标及内容类型、Git 跟踪/改动状态和占用进程；确认范围内全部为可丢弃产物。递归操作不得跟随符号链接/目录联接或跨挂载点；链接本身须单独核对后按明确路径解除。先在进度说明中列出清理路径与原因；命令使用逐个明确路径，不使用通配符、空值变量或未经校验的路径拼接，不以 `git clean -fdx`、全局 prune 等扩大范围。

## 现场保留与交付

失败或中断的升级/验收现场，以及明确要求保留的报告、日志和备份，须保留到问题处理完成且已有足够的复核/交接证据；摘要不能替代仍需复核的原始证据。存在专项保留要求时优先遵守。清理已完成任务的临时副本前，将必要的结果和证据摘要保存到保留位置；结束时说明已清理与仍保留的内容。
