# AI 机器人与交易复盘

> 文档状态：当前规范。适用范围：AI 机器人的使用、配置与功能边界。

本版本提供一个全局机器人，支持模型配置、回放历史交易的单笔复盘，以及单个回放会话的归纳。右下角机器人图标、历史日志中的“交给 AI”“总结本会话”均打开同一窗口。

机器人图标可拖动，位置在本机浏览器保存；也可聚焦后用方向键微调。拖动结束不会打开窗口，正常点击、Enter 或空格才打开。窗口打开后图标隐藏，最小化或关闭后在原位置重新出现；缩小视口时自动限制在可见范围内。

提问靠右、回答靠左显示：提问使用浅蓝背景，回答使用浅 Slate 背景，气泡内文字保持左对齐，附身份与消息时间（含本机时区）。回答支持默认折叠的“思考过程”，只展示服务实际返回的 `reasoning_content` 或文本 `reasoning`；没有返回该字段的模型和旧消息不补造思考内容。接入字段参见 [DeepSeek 思考模式](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)。

思考内容与正文分开展示、保存。固定资料模式的普通历史只发送正文；工具模式另存完整 assistant/tool 协议单元，DeepSeek 兼容策略续传服务实际返回的思考字段。旧消息只作为标注的历史参考。时间为最终回答请求的实测耗时，包含网络等待；思考耗时截至正文首次返回。工具中间正文不拼成多份最终答案。展示元数据与供应商续传记录分开；不完整响应不保存为成功回答。回答卡片中的“本次用量与上限”显示供应商已报告的 Token 和运行限制，不估算费用。

## 配置与启动

首次安装按[项目 README](../../README.md#快速开始)完成。已有安装统一按[升级指南](../operations/upgrade.md#数据库版本基线与升级边界2026-10-27)核对实际数据库、备份并选择适用升级入口；本专题不提供另一套数据库升级命令。

AI 所用迁移 `20261016090000_add_ai_tool_execution` 与 `20261016100000_add_ai_chart_variants` 已包含在 v1.0 基线。已达基线且结构无变化时，不因启用 AI 重跑旧初始化或兼容升级；低于基线须先按 v1.0 tag 的完整流程升级，后续结构变化遵守新的升级链路规则。

为本地服务配置一次独立的 AI 加密主密钥：

~~~powershell
node scripts/tools/setup-ai-key.mjs
~~~

脚本将随机主密钥写入被 Git 忽略的本地 `.env`，不输出密钥。已有有效配置保持原样，无效配置报错并保留；重启服务后生效。它不替换原行情加密主密钥。

其他部署可以在服务环境配置稳定的 `AI_ENCRYPTION_KEY`（32 字节、标准 Base64）；Compose 已提供映射。数据库、对应存储文件与原主密钥须一起备份，不要在另一台机器上重新生成主密钥后直接读取原密文。

AI 配置位于独立页面 `/settings/ai`，首页提供入口；机器人窗口顶部的设置图标在新标签页打开该页面，原聊天和草稿保留。进入“大模型”，添加端点名称、Base URL 和可选 API Key，选择启用的端点。点击“拉取模型”后，在同一行的“默认模型”下拉框中选择；首次拉取会预选返回的第一个模型，重新拉取时保留仍可用的当前选择。无需手动输入模型 ID，也不再显示独立的模型标签列表。Base URL 应包含服务商所需版本路径，界面预览最终地址；高级选项允许完整请求地址，并可选择 `max_tokens` 或 `max_completion_tokens`。

当前适配 OpenAI-compatible Chat Completions。保存、打开设置和切换模型均不自动探测；仅提供“测试连接”，由用户手动触发一次简短文本请求，可能收费。拉取和测试前会先保存当前表单，拉取后的模型选择需点击“保存设置”持久化。测试不探测图片、工具或结构化输出能力，也不表示模型已具备这些能力；实际使用不强制前置能力验证，不支持的请求由服务错误反馈。不会自动重试付费请求或切换供应商。

独立页面的“取消”恢复最近读取或保存成功的表单；保存成功后通知已打开的聊天页刷新配置，返回聊天页时也会重新读取。正在运行的任务继续使用原模型快照。

“助手个性化”页签可修改助手名称（1–32 个 Unicode 字符，自动去除首尾空白）。点击“保存设置”后，聊天窗口标题、历史及后续回答的署名、悬浮入口提示同步使用新名称，其他标签页也会更新；刷新后保留。“恢复默认名称”将表单改回“AI 机器人”，仍需保存才生效。名称只影响界面显示，不改变模型提示词；旧配置自动使用默认名称，无需数据库迁移。

已保存密钥只返回状态，输入框以 `······` 提示已有密钥，留空保留。“清除”是说明文字右侧的紧凑按钮，点击后移除占位提示并显示待保存状态，保存设置后才生效；取消保留原密钥。“眼睛”仅显示本次新输入。

所有技能统一使用“大模型”中启用的端点及其默认模型。技能页只配置启停和任务提示词，并可经确认恢复默认提示词；任务提示词不能解除服务端边界。旧版技能的端点/模型覆盖字段读取时忽略，保存时不再写入，其他配置保持原样。已有运行及其重试仍沿用该运行固定的原模型快照。

## 直接提问与自动资料

聊天窗口不再提供角色选择。发送时由当前模型识别普通讨论、图表分析、复盘草稿或整个会话报告，再进入相应流程；报告后的普通追问不会因为上一轮生成过报告而重复整会话批处理。只有明确要求撰写或优化复盘正文时才生成可采用草稿。

窗口输入框上方显示下一次提问的资料范围。回放页面自动关联当前会话，可见图表随平移更新；复盘编辑器打开时优先关联该笔、所选模板与未保存草稿。发送时固定快照，进行中的分析不随页面或进度改变。每个周期每页最多 200 根，超过范围需分页；重建图不含手动画线。没有页面对象时可以沿用当前聊天上次的资料；新聊天不会猜测最近的数据库会话。

“资料”菜单可切回自动关联、指定其他资料或使用普通问答。手动指定的范围在当前浏览器按聊天记忆；查看历史消息的“参考来源”只查看证据，点击“后续提问使用这些资料”才改变后续范围。对象不明确、交易编号不存在/有歧义或模板未明确时保留问题并提示补充，不自动搜索其他会话。

自动识别会额外发起一次有界模型请求，其成功记录及用量纳入运行；普通工具任务默认最多合计 6 次、整个会话默认最多 750 次，可在上限设置中调整。识别失败、取消或等待补充时不自动重试。首版实施背景见[自动交互历史记录](ai-assistant-interaction.md)，当前规则以本文为准。

## 单笔复盘

历史日志中双击复盘单元格，选择模板并编辑原文后点击“交给 AI”，直接要求生成或优化复盘正文。系统固定模板、未保存原文、交易事实与图表；也可从机器人“资料 → 指定其他资料”指定会话、单笔交易和模板。未选择模板且未要求模板时使用自由格式；明确要求按模板时，只有唯一模板才自动选取，否则提示指定。

输入例如“按模板完善复盘，保留我的观点，没有记录的原计划和情绪不要编造”。通过长度及来源校验后，可点击“采用到复盘编辑器”；采用只更新编辑草稿，仍需核对并点击原编辑器的“保存复盘”。

- 正文保留 2,000 个 Unicode 字符，详细分析及证据另存于聊天、运行和固定资料中。
- 原文、会话或交易结果改变时提示冲突；不静默覆盖。
- 保存人工与 AI 辅助来源，AI 辅助文字不作为独立成交证据。
- 生成、失败或停止不改变成交、订单、Setup、交易理由或检查快照。
- 普通文本或未通过结构/来源校验的回答可以阅读，但不能直接采用。

## 单会话分析

直接要求“总结整个会话”会覆盖该会话当前有效结果内的全部已结束日志，包含没有复盘的记录，不受表格分页影响。“总结本会话”入口也可带入对应资料。默认快速分析，明确要求逐笔审阅全部图表或在指定资料中选择完整深度时才准备全量图片。

| 模式 | 输入与用途 |
| --- | --- |
| 快速：文字与统计 | 交易、笔记、检查快照与程序指标；明确未审阅全部图表。 |
| 完整：逐笔图表 | 逐笔准备图表，分批阅读后汇总；长持仓可能分成多张图。 |

发送前显示资料范围；每条消息的参考来源可查看冻结时点、覆盖和图片，运行中显示已处理批次数。

分析使用独立 Node 子进程，保存批次和分层汇总检查点。关闭窗口不会取消后台分析，“停止”会取消。中断或运行时限到达后可显式继续，沿用原资料和模型；状态不明的付费步骤可能再次计费。

报告从“已保存会话报告”查看；复盘、进度或纠错结果改变后保留旧证据并标注变化。删除聊天不删除正式复盘或已保存报告。候选规则附支持、反例及验证动作，不自动写入原策略。

## 证据与统计口径

- 总体统计复用完整持仓交易 `PaperTrade`，净盈亏为 `grossPnl - fees`，滑点已在成交价中体现，不重复扣除。
- FIFO 行数与完整持仓交易数分别显示；分组价差明确为未扣费行口径，不宣称已可靠分摊手续费。
- 风险缺失时不补造 R 分母；未结束交易不混入已结束交易胜率。
- 成交和已记录订单操作按当前 projection、持仓周期和源序号关联；旧资料无法可靠关联时说明缺口。
- 消息显示实际模型及参考时点。模板、原文、检查快照、交易与图表固定到发送快照，切页不改变运行对象。
- 图表复用源周期聚合与块级摘要，默认截至平仓；形成中的高周期柱不读未来源 K 线。
- 重建图不是原始入场截图，不能恢复逐笔路径。当前手动画线和 DOM 标签未并入图，EMA 使用截图窗口，不能声称全历史递推。
- 上传图片单列为用户参考资料，不自动证明拍摄时点和交易归属；模型是否支持图片以服务实际响应为准。

业务读取工具只在绑定的单笔/会话快照内读取事实、模板、统计和图片，不能查询全库；工具集合按范围与图表可用性动态注册，以 `lib/ai/tools.ts` 为准。图表工具现为 `get_chart_images`，默认当前图表和当前周期；用户明确要求时，可读取最多 4 个周期的多张图片。新工具、固定资料和会话批次均不向模型输出逐根 OHLCV 数组。单笔范围提供详情与模板，会话范围另有列表与统计；允许取图的范围还提供 `get_chart_images` 和向当前回复附图的 `display_images`，二者不修改交易事实。自动关联的快速会话允许在固定版本、交易身份与截止点内生成交易图表并向模型交付图片，不代表已审阅全部图。回答的“资料读取记录”默认折叠，刷新后可恢复，与思考过程分开。Embedding、知识库、跨会话研究、Setup 扣费净额分组及下单指导尚未接入。

图片按固定窗口、周期、偏好及截止点匹配，每个周期窗口最多 200 根，增加周期不再改变原图片窗口。当前图表包含范围内已结束交易的自动标注，单笔图片只标该笔；随图向模型发送渲染说明、完整图例及图中编号到日志编号、内部编号、账户和交易引用的映射。已明确的图片可预先准备；运行中缺图时，浏览器领取持久任务、离屏重绘、上传后继续回答。隐藏的 EMA 不参与预热。多周期分别有有界读取预算，单个周期失败不抹去其他成功图片。保持页面可见可完成截图；关闭标签页后无法生成新图，但已上传图片仍可用于后台分析。完整流程、租约/取消规则和边界见 [图表图片工具](ai-chart-images.md)。

端点高级设置可明确选择通用/DeepSeek 工具策略及流式/非流式工具轮次，不按模型名称猜测。工具请求被拒绝时不会自动重发；可在“聊天操作 → 兼容设置”勾选“使用固定资料模式”新建运行。旧运行和检查点继续使用原固定资料流程。普通工具运行默认最多 6 次模型请求（自动分派占一次）、12 次工具调用，每轮最多 4 个并串行执行；全会话保留程序批处理，分派、批次及最终核对默认共享 750 次总额度。首版实施和当时验收见[历史实施记录](ai-function-calling-implementation.md)，不作为当前能力限制或复测证明。

## 限制、存储和部署

限制见 `lib/ai/schema.ts`：单个范围最多 5,000 条日志、100 张重建图；手动图片一次最多 6 张、每张 4 MiB。输入按字符及图片预算估算，并非供应商的真实 Token 容量承诺。

在“AI 配置 → 用量与上限”设置全局默认值；聊天输入区的“调整上限”仅用于本聊天后续请求，刷新后恢复全局值。失败卡片提供“调整并重试”，沿用原问题、模型和资料；会话归纳提供“调整并继续”，保留已完成批次及累计用量。仅应用设置不会重新调用模型。

可配置项及允许范围以 [limits.ts](../../lib/ai/limits.ts) 为准：每次输出默认 4,096 Token（256–65,536）；单次输入估算默认 48,000 字符；普通问答累计输入 240,000 字符、6 次模型请求；工具 12 次、累计结果 256 KiB；会话归纳 750 次模型请求、5,000,000 累计字符；单次等待 120 秒、整次执行 300 秒。输入、工具与等待选项默认折叠。实际服务仍可能有更低的模型输出或上下文上限。单条工具结果、图片、图表与资料范围保护保持独立。

输出上限是**每次模型请求**的输出 Token，并非整段聊天的总 Token。卡片单独显示本次运行累计输入/输出、最近一轮输出与当前上限，以及模型请求、工具和字符保护。累计 Token 包含本次分派、工具轮次和最终回答；使用服务实际报告，未报告的部分显示未知或已知下限。截断与失败请求的已报告用量也保留。字符估算并不是实际输入 Token，不显示虚假的模型上下文容量。

每次准备/运行固定有效上限，之后修改全局配置不会改变在途请求。达到限制时说明具体资源与已用或预计所需值（含为汇总预留的容量），可提高对应项后显式重试/继续；失败的尝试同样计数，继续会话不会重置累计预算。本次配置使用现有 JSON 字段，无数据库结构变更。

AI 表、复盘来源与报告保存于 SQLite，图片位于 `storage/ai/`。完整备份包括数据库、图片和主密钥；独立交易日志 ZIP 不包含回放 AI 报告。当前不自动批量清理证据或图片。

Dockerfile 已补充 worker 所需 `scripts/`、`lib/` 与 `tsconfig.json`，需发布包含当前代码的镜像。本地 worker 与主应用沿用同一数据库和环境。
